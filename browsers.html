Раздел 04 · Платформа выполнения веб-приложений

Браузеры: архитектура, движки и конвейер рендеринга

Браузер — это не просто программа для отображения веб-страниц. Это сложная платформа, которая обрабатывает HTML, CSS и JavaScript, управляет сетевыми запросами, обеспечивает безопасность и выполняет код в изолированных процессах.

АрхитектураДвижкиРендерингБезопасность

1. Что такое браузер и как он работает

Браузер — приложение, которое загружает веб-ресурсы с сервера или локального хранилища, интерпретирует HTML, CSS и JavaScript, и отображает результат в виде интерактивной страницы.

Современный браузер — это не монолитная программа, а набор cooperating процессов и потоков, каждый из которых отвечает за свою задачу: пользовательский интерфейс, сетевые запросы, рендеринг, выполнение JavaScript и другие.

UI-процесс

Управляет интерфейсом браузера: адресная строка, вкладки, кнопки навигации.

Renderer-процесс

Обрабатывает и отображает содержимое вкладки: HTML, CSS, JavaScript.

Network-процесс

Управляет сетевыми запросами, кэшем и загрузкой ресурсов.

2. Архитектура браузера

Современные браузеры используют многопроцессную архитектуру для изоляции вкладок, повышения стабильности и безопасности.

2.1. Изоляция процессов

Каждая вкладка обычно выполняется в отдельном renderer-процессе. Это означает, что если одна вкладка зависает или падает, другие вкладки продолжают работать. Изоляция также повышает безопасность: компрометация одной страницы не даёт прямого доступа к памяти других вкладок.

2.2. Site Isolation

Site Isolation — механизм, который разделяет документы из разных сайтов в разные процессы, даже если они находятся в одной вкладке (например, через iframe). Это снижает риск атак типа Spectre и ограничивает последствия уязвимостей движка рендеринга.

3. Движки браузера

Браузер состоит из нескольких ключевых компонентов, каждый из которых реализует свою часть веб-платформы.

КомпонентНазначениеПримеры
Движок рендерингаРазбирает HTML и CSS, строит DOM и CSSOM, вычисляет layout, paint и composite.Blink (Chrome, Edge), Gecko (Firefox), WebKit (Safari).
Движок JavaScriptРазбирает и выполняет JavaScript-код.V8 (Chrome, Edge), SpiderMonkey (Firefox), JavaScriptCore (Safari).
Сетевой стекУправляет HTTP/HTTPS-запросами, кэшем, DNS, TLS.Реализация зависит от браузера.
Графический стекКомпозиция слоёв, отрисовка через GPU.Skia, Core Graphics.

3.1. Основные движки

  • Blink — движок рендеринга Chromium, используется в Chrome, Edge, Opera, Brave и других.
  • Gecko — движок рендеринга Firefox.
  • WebKit — движок рендеринга Safari (и исторически Chrome).
  • V8 — JavaScript-движок Chromium.
  • SpiderMonkey — JavaScript-движок Firefox.
  • JavaScriptCore — JavaScript-движок WebKit.

4. Парсинг HTML и CSS

Когда браузер получает HTML-документ, он запускает HTML-парсер. Парсер читает поток символов, токенизирует разметку и строит дерево DOM. Парсинг может продолжаться по мере получения данных из сети.

HTML-документ (байты)
  ↓
HTML-парсер (токенизация)
  ↓
DOM (дерево узлов)
  ↓
Совместная обработка с CSS и JavaScript
  ↓
Отображение страницы

4.1. CSS-парсер

CSS-парсер читает таблицы стилей и строит CSSOM (CSS Object Model) — дерево CSS-правил. CSSOM используется для вычисления стилей элементов DOM.

CSS-файл (байты)
  ↓
CSS-парсер
  ↓
CSSOM (дерево правил)
  ↓
Вычисление стилей (стили + DOM = Render Tree)

4.2. Блокирующие ресурсы

CSS является render-blocking ресурсом: браузер не начинает рендеринг, пока не загрузит и не разберёт все CSS-файлы. JavaScript по умолчанию также блокирует парсинг HTML, если не указан атрибут defer или async.

5. DOM и CSSOM

DOM (Document Object Model) — объектное представление HTML-документа в виде дерева узлов. CSSOM — объектное представление CSS-правил. Вместе они формируют основу для рендеринга и взаимодействия с JavaScript.

DOM:
Document
└── html
    ├── head
    │   └── title
    └── body
        ├── h1
        └── p

CSSOM:
body { color: black; }
  └── h1 { color: blue; }
      └── p { font-size: 16px; }

5.1. Render Tree

Render Tree — дерево элементов, которые будут отображены на странице. Оно строится на основе DOM и CSSOM, но исключает невидимые элементы (например, display: none).

5.2. Layout (Reflow)

Layout — вычисление геометрии каждого элемента: позиция, размеры, отступы. Это дорогостоящая операция, особенно для сложных раскладок.

5.3. Paint

Paint — подготовка операций рисования: заполнение пикселей, текст, границы, тени, градиенты.

5.4. Composite

Composite — сборка слоёв в итоговый кадр. Современные браузеры используют GPU для ускорения композиции.

6. Конвейер рендеринга

Конвейер рендеринга — последовательность шагов, которые браузер выполняет для отображения страницы.

6.1. Стоимость изменений

Разные CSS-свойства запускают разную работу браузера:

  • Layout-triggering: изменение width, height, margin, padding, font-size требует пересчёта геометрии.
  • Paint-triggering: изменение color, background, border, box-shadow требует перерисовки.
  • Composite-only: изменение transform, opacity может быть обработано на этапе композиции без layout и paint.
Оптимизация: для плавных анимаций предпочитай transform и opacity вместо изменения геометрии. Но конкретный путь зависит от браузера, контекста и графического конвейера.

7. JavaScript и Event Loop

JavaScript выполняется в renderer-процессе в основном потоке (main thread). Этот поток обрабатывает JavaScript, события, layout и paint. Длинная синхронная задача в main thread блокирует пользовательский интерфейс.

7.1. Event Loop

Event Loop — механизм координации выполнения синхронного кода, микрозадач (Promise, queueMicrotask) и макрозадач (setTimeout, setInterval, I/O).

Порядок выполнения:
1. Синхронный код
2. Микрозадачи (Promise.then, queueMicrotask)
3. Рендеринг (requestAnimationFrame, layout, paint)
4. Макрозадачи (setTimeout, setInterval, I/O)
5. Повторить с шага 2

7.2. Main Thread и Web Workers

Web Workers выполняют JavaScript в отдельном потоке без доступа к DOM. Это позволяет вынести тяжёлые вычисления из main thread и не блокировать пользовательский интерфейс.

8. Сеть и ресурсы

Браузер управляет сетевыми запросами через HTTP/HTTPS-стек. Он обрабатывает DNS-разрешение, TLS-рукопожатие, кэширование, загрузку ресурсов и обработку ответов.

8.1. HTTP-запросы

GET /index.html HTTP/1.1
Host: example.com
User-Agent: Mozilla/5.0
Accept: text/html
Cookie: session=abc123

8.2. Кэширование

Браузер кэширует ресурсы для ускорения повторных загрузок. Управление кэшем происходит через HTTP-заголовки: Cache-Control, ETag, Last-Modified.

8.3. Resource Hints

<link rel="preload" href="font.woff2" as="font">
<link rel="prefetch" href="next-page.html">
<link rel="preconnect" href="https://api.example.com">
<link rel="dns-prefetch" href="https://cdn.example.com">

10. Безопасность браузера

Браузер применяет множество механизмов для защиты пользователей от вредоносного кода и атак.

10.1. Same-Origin Policy (SOP)

SOP ограничивает взаимодействие между документами из разных источников (origin). Origin определяется схемой, хостом и портом.

10.2. CORS

CORS (Cross-Origin Resource Sharing) — механизм, с помощью которого сервер через HTTP-заголовки сообщает браузеру, каким другим источникам разрешено читать определённые ответы.

10.3. Content Security Policy (CSP)

CSP ограничивает источники, из которых можно загружать скрипты, стили, изображения и другие ресурсы. Это снижает риск XSS-атак.

10.4. Subresource Integrity (SRI)

SRI проверяет, что загруженный ресурс соответствует ожидаемому хэшу. Если файл был изменён, браузер не выполнит его.

10.5. Sandbox и Permissions

Атрибут sandbox ограничивает возможности iframe. Permissions API управляет доступом к камере, микрофону, геолокации и другим чувствительным API.

12. Производительность

Быстродействие — не только скорость загрузки HTML. Пользователь оценивает, когда появляется основной контент, как быстро интерфейс реагирует на действия и насколько стабильно располагаются элементы страницы.

12.1. Core Web Vitals

МетрикаЧто измеряет
LCPВремя отображения самого крупного контентного элемента.
INPЗадержку визуального отклика на взаимодействия.
CLSНакопленную неожиданную нестабильность расположения элементов.

12.2. Практические приёмы

  • Уменьшать объём критических ресурсов.
  • Использовать подходящие форматы и размеры изображений.
  • Отложенно загружать изображения ниже первого экрана.
  • Избегать длинных синхронных задач.
  • Не вызывать синхронный layout многократно.
  • Не анимировать свойства, которые постоянно меняют геометрию.

13. Совместимость браузеров

Стандарты описывают ожидаемое поведение веб-платформы, а браузерные движки реализуют эти требования. Реализации развиваются не одновременно, а отдельные функции могут иметь ограничения или особенности.

13.1. Как проверять поддержку

  • MDN Browser Compatibility Data — таблицы совместимости.
  • Can I Use — быстрый просмотр поддержки функций.
  • Web Platform Tests — тесты соответствия стандартам.
  • Реальные тесты — проверка целевых браузеров.

13.2. Progressive Enhancement

Прогрессивное улучшение — подход, при котором базовое содержание и основные действия работают на надёжном фундаменте, а дополнительные возможности подключаются там, где они поддерживаются.

14. Progressive Web Apps и офлайн-режим

Progressive Web App (PWA) — веб-приложение, которое использует ряд браузерных возможностей, чтобы приблизить пользовательский опыт к приложению: устанавливаемость, работа с кэшем, офлайн-сценарии, интеграция с ОС.

14.1. Основные составляющие

  • Web App Manifest — описание названия, иконок, стартового URL.
  • Service Worker — фоновый скрипт, который может перехватывать fetch-запросы.
  • Cache Storage — хранение ответов, которыми может управлять Service Worker.
  • HTTPS — защищённый контекст для многих функций PWA.

15. Практический рабочий процесс

Браузер — не только место, где проверяют готовый сайт. Это ежедневная рабочая среда для разработки.

  1. Создать страницу. Подготовить HTML, CSS и JavaScript.
  2. Открыть в браузере. Проверить реальное поведение.
  3. Изучить DOM и стили. В Elements проверить структуру и стили.
  4. Проверить ошибки. В Console найти исключения.
  5. Проверить сеть. В Network найти неудачные запросы.
  6. Поставить breakpoint. В Debugger остановить выполнение.
  7. Измерить производительность. Записать Performance profile.
  8. Проверить совместимость. Пройти сценарии в целевых браузерах.

16. Практические задания

Задание 1. Проследи загрузку страницы
  1. Открой любой сайт и DevTools → Network.
  2. Включи Preserve log и перезагрузи страницу.
  3. Найди основной запрос типа Document.
  4. Посмотри status code, response headers, initiator и timing.
  5. Выбери CSS, JS, image и сравни типы запросов.
Задание 2. Исследуй DOM и CSSOM
  1. Создай страницу с заголовком, абзацем и кнопкой.
  2. Открой Elements и найди соответствующие узлы DOM.
  3. Измени текст элемента через панель.
  4. Посмотри computed styles.
Задание 3. Найди причину медленного интерфейса
  1. Открой Performance и запиши взаимодействие.
  2. Найди длинные задачи на Main thread.
  3. Изучи вызванные ими функции.
  4. Сформулируй гипотезу об узком месте.
