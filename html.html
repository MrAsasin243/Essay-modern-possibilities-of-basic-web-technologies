HTML: структура, смысл и содержимое страницы

HTML определяет, какие элементы присутствуют в документе, как они связаны между собой и какое значение имеют. Это не просто набор тегов: HTML задаёт семантическую структуру, предоставляет формы и встроенные элементы интерфейса, описывает мультимедиа и связывает документ с ресурсами.

1. Что такое HTML и за что он отвечает

HTML (HyperText Markup Language) — язык разметки гипертекста, используемый для описания структуры и семантики веб-документов.

HTML не является языком программирования общего назначения: в нём нет привычной модели произвольных вычислений, циклов и функций. Его задача — разметить содержимое документа так, чтобы браузер и другие программы могли определить, что представляет собой каждый фрагмент.

HTML

Структура и смысл: заголовки, абзацы, формы, ссылки, изображения.

CSS

Представление: цвета, типографика, размеры, сетки и адаптивность.

JavaScript

Поведение: алгоритмы, события, динамика и взаимодействие с API.

Важная оговорка. Это разделение описывает основные роли, но не является жёсткой границей. HTML уже содержит встроенное поведение некоторых элементов, CSS умеет создавать анимации и реагировать на состояния, а JavaScript может менять структуру и оформление документа.

Сегодня HTML развивается как Living Standard — живой стандарт, который обновляется непрерывно. Поэтому HTML5 — исторически распространённое название поколения HTML, а не отдельная современная версия, которую нужно выбирать в документе.

2. Как HTML обрабатывается браузером

Когда браузер получает HTML-документ, он запускает HTML-парсер. Парсер читает поток символов, разбирает разметку и формирует структуру документа. Разбор может продолжаться по мере получения данных из сети.

2.1. DOM — объектная модель документа

DOM (Document Object Model) — программное представление документа в виде дерева узлов и объектов. Браузер строит DOM при разборе HTML. JavaScript может читать и изменять эту структуру: добавлять элементы, менять текст и атрибуты, удалять узлы и подписываться на события.

<body>
  <h1>Мой сайт</h1>
  <p>Изучаю <strong>HTML</strong>.</p>
</body>
Document
└── html
    ├── head
    └── body
        ├── h1
        │   └── "Мой сайт"
        └── p
            ├── "Изучаю "
            └── strong
                └── "HTML"

DOM не тождествен исходному HTML-файлу. Во время построения дерева браузер исправляет некоторые ошибки разметки по правилам HTML, а после загрузки JavaScript может изменить DOM. В результате текущее дерево может отличаться от текста, который пришёл с сервера.

Связь с будущим разделом JavaScript: методы вроде document.querySelector(), свойства textContent и методы append() работают с DOM, а не редактируют исходный HTML-файл на диске.

3. Синтаксис HTML

3.1. Элемент и тег

Элемент — единица документа, а теги — синтаксические конструкции, которыми обычно обозначают его начало и конец.

<p>Привет, мир!</p>
  • <p> — открывающий тег.
  • Привет, мир! — текстовое содержимое.
  • </p> — закрывающий тег.
  • Вся конструкция — элемент абзаца.

Элементы могут вкладываться друг в друга. Вложенность должна соответствовать правилам содержимого HTML.

<div>
  <h1>Заголовок</h1>
  <p>Текст с <strong>выделением</strong>.</p>
</div>

3.2. Атрибуты

Атрибуты задают элементу дополнительные параметры. Обычно они указываются в открывающем теге в форме имя="значение".

<a href="https://example.com" target="_blank">
  Открыть сайт
</a>

Здесь href задаёт адрес ссылки, а target — контекст её открытия.

Распространённые глобальные атрибуты

АтрибутНазначение
idИдентификатор элемента в пределах документа; обычно должен быть уникальным.
classНабор имён классов для группировки элементов и выбора их в CSS или JavaScript.
styleВстроенное CSS-описание оформления конкретного элемента.
titleДополнительная подсказка или пояснение.
langЯзык содержимого элемента.
dirНаправление текста: например, слева направо или справа налево.
hiddenУказывает, что элемент не должен отображаться обычным образом.
tabindexВключает элемент в клавиатурную навигацию и задаёт его порядок фокуса.
contenteditableРазрешает редактирование содержимого пользователем.
draggableУчаствует ли элемент в механизме перетаскивания.
data-*Пользовательские данные, связанные с конкретным элементом.
aria-*Дополнительная семантическая информация для вспомогательных технологий.
<div id="profile" class="user-card active"
     data-user-id="125">
  Профиль пользователя
</div>

3.3. Пустые элементы

Некоторые элементы не могут содержать дочерние узлы и не имеют закрывающего тега. Их называют void elements.

<img src="photo.jpg" alt="Фотография">
<br>
<hr>
<input type="text">
<meta charset="UTF-8">

В HTML не нужно записывать для них отдельные закрывающие теги. Косая черта перед > не превращает обычный HTML в XML.

3.4. Комментарии и символьные ссылки

<!-- Комментарий: браузер не показывает его как обычный текст -->

<p>5 &lt; 10</p>
<p>HTML &amp; CSS</p>
<p>&copy; 2026</p>

Символьные ссылки нужны, чтобы записывать зарезервированные символы и специальные знаки. Например, &lt; отображается как знак «меньше».

3.5. Вложенность и восстановление ошибок

Браузеры пытаются восстановить документ при многих синтаксических ошибках, однако результат восстановления не всегда совпадает с намерением автора.

<!-- Некорректная вложенность -->
<p>Первый абзац
  <p>Второй абзац</p>
</p>

<!-- Корректная запись -->
<p>Первый абзац</p>
<p>Второй абзац</p>

4. Каркас HTML-документа

Ниже — типичная основа HTML-страницы. Она подходит для большинства обычных документов.

<!doctype html>
<html lang="ru">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Моя страница</title>
  <meta name="description" content="Краткое описание страницы">
  <link rel="stylesheet" href="styles.css">
  <script src="app.js" defer></script>
</head>
<body>
  <h1>Заголовок страницы</h1>
  <p>Содержимое документа.</p>
</body>
</html>
ЧастьНазначение
<!doctype html>Объявляет HTML-документ и включает стандартный режим отображения браузера.
<html>Корневой элемент. Атрибут lang сообщает основной язык документа.
<head>Метаданные, название, ссылки на ресурсы и настройки документа.
<body>Основное содержимое, предназначенное для документа.

4.1. Назначение важных элементов head

  • meta charset="utf-8" — указывает кодировку документа.
  • meta name="viewport" — задаёт параметры области просмотра, особенно важные для мобильных устройств.
  • title — название документа, используемое во вкладке и другими системами.
  • meta name="description" — краткое описание страницы; его использование поисковиком зависит от контекста.
  • link rel="stylesheet" — подключает внешнюю таблицу стилей.
  • script — подключает или содержит сценарий.
Не путай: содержимое head — не «скрытый блок страницы». Это область метаданных. Большинство обычного видимого содержимого размещают в body.

5. Структура и семантика документа

Семантика — это смысловое назначение элемента. Например, <nav> обозначает навигационную область, а <main> — основное содержимое документа.

ЭлементНазначение
headerВводная или заголовочная часть страницы либо раздела.
navОбласть с основными навигационными ссылками.
mainОсновное уникальное содержимое страницы.
articleСамостоятельный материал, который может существовать отдельно: статья, публикация, карточка новости.
sectionТематически объединённый раздел, обычно с заголовком.
asideДополнительное содержимое, связанное с основным или окружающим разделом.
footerЗаключительная часть страницы или раздела.
addressКонтактная информация для ближайшего подходящего раздела или документа.
divУниверсальный контейнер без собственной семантики.
spanУниверсальный строчный контейнер без собственной семантики.
<body>
  <header>
    <h1>Новости технологий</h1>
  </header>

  <nav aria-label="Основная навигация">
    <a href="/">Главная</a>
    <a href="/articles">Статьи</a>
  </nav>

  <main>
    <article>
      <h2>Новая публикация</h2>
      <p>Текст статьи...</p>
    </article>
    <aside>Связанные материалы</aside>
  </main>

  <footer>Контактная информация</footer>
</body>

Семантическая разметка помогает вспомогательным технологиям и программам понимать структуру. Она также упрощает сопровождение кода. Визуальное оформление само по себе не делает элемент семантическим: div, стилизованный как заголовок, всё равно остаётся обычным контейнером.

7. Гиперссылки и навигация

Гиперссылки связывают документы и ресурсы — это одна из основ гипертекста. Основной элемент — <a>. Атрибут href задаёт адрес назначения.

<!-- Внешний ресурс -->
<a href="https://example.com">Открыть сайт</a>

<!-- Новая вкладка -->
<a href="https://example.com" target="_blank" rel="noopener">
  Открыть в новой вкладке
</a>

<!-- Переход к элементу с id="contacts" -->
<a href="#contacts">Контакты</a>

<!-- Почтовый адрес и телефонный URI -->
<a href="mailto:hello@example.com">Написать</a>
<a href="tel:+358123456789">Позвонить</a>

<!-- Подсказка браузеру скачать ресурс -->
<a href="guide.pdf" download>Скачать PDF</a>

URL может быть абсолютным или относительным. Относительные адреса вычисляются относительно адреса документа и, при наличии, элемента <base>. Атрибут target="_blank" открывает ссылку в новом browsing context; для внешних ссылок полезно явно задавать подходящий rel и продумывать пользовательский опыт.

8. Таблицы

Таблицы предназначены для данных, где есть отношения между строками и столбцами. Не следует использовать их вместо CSS Grid или Flexbox для компоновки всей страницы.

ЭлементНазначение
tableТабличная структура.
captionНазвание таблицы.
theadГруппа строк заголовка.
tbodyОсновная группа строк.
tfootНижняя группа строк, например итоги.
trСтрока.
thЗаголовочная ячейка.
tdЯчейка данных.
colgroup, colОписание столбцов или групп столбцов.
<table>
  <caption>Оценки студентов</caption>
  <thead>
    <tr><th scope="col">Студент</th><th scope="col">Математика</th></tr>
  </thead>
  <tbody>
    <tr><th scope="row">Алексей</th><td>5</td></tr>
    <tr><th scope="row">Иван</th><td>4</td></tr>
  </tbody>
</table>

Для доступности таблиц важно правильно связывать заголовки с ячейками. Для простых таблиц обычно достаточно th и scope; для сложных структур могут понадобиться более точные связи.

ЭлементРоль

inputОднострочное поле или другой элемент управления.
textareaМногострочный ввод.
buttonКнопка: отправка формы, сброс или обычное действие.
labelПодпись, связанная с управляющим элементом.
select, optionСписок вариантов выбора.
optgroupГруппа вариантов.
fieldset, legendГруппировка полей и название группы.
datalistПодсказки возможных значений для поля.
outputРезультат вычисления или действия.
progressХод выполнения задачи.
meterИзмеренное значение в известном диапазоне.

9.1. Типы input

Один элемент input способен создавать разные виды полей и контролов. Конкретный интерфейс частично зависит от браузера и операционной системы.

ТипНазначение
textОбычный текст.
passwordПароль; ввод визуально маскируется.
emailЭлектронная почта; поддерживает базовую проверку формата.
numberЧисловое значение.

searchПоисковая строка.
date, timeДата и время.

month, weekМесяц и неделя.
colorВыбор цвета.
rangeПолзунок для числового диапазона.
checkboxНезависимый флажок.
radioВыбор одного варианта из группы.
fileВыбор файла или файлов.
hiddenСкрытое поле, отправляемое вместе с формой.
submit, reset, buttonКнопки отправки, сброса и обычного действия.
imageКнопка отправки формы на основе изображения.

9.2. Пример формы

<form action="/register" method="post">
  <label for="email">Электронная почта</label>
  <input id="email" name="email" type="email" required>

  <label for="age">Возраст</label>
  <input id="age" name="age" type="number" min="18" max="100" required>

  <button type="submit">Зарегистрироваться</button>
</form>

У form важны атрибуты action (адрес обработчика), method (метод запроса), enctype (кодирование тела запроса). У полей важен атрибут name: именно по нему формируются имена отправляемых значений.

9.3. Встроенная проверка ввода

HTML умеет выполнять базовую клиентскую валидацию без JavaScript.

АтрибутНазначение
requiredПоле обязательно для заполнения.
min, maxМинимальное и максимальное значение.
stepДопустимый шаг числового значения.
minlength, maxlengthМинимальная и максимальная длина текста.
patternШаблон допустимого текстового значения.
placeholderПример или подсказка внутри поля.
autocompleteПодсказка браузеру о назначении поля и возможности автозаполнения.
multipleРазрешение нескольких значений для поддерживающих это типов.
Безопасность: клиентская валидация улучшает удобство, но не защищает сервер. Запрос можно сформировать вручную, поэтому сервер обязан повторно проверять тип, формат, диапазоны, права доступа и допустимость каждого значения.

9.4. Отправка файлов

<form action="/upload" method="post" enctype="multipart/form-data">
  <label for="file">Выберите файл</label>
  <input id="file" name="file" type="file" required>
  <button type="submit">Загрузить</button>
</form>

Для файловой отправки обычно используют POST и multipart/form-data. Сервер должен проверять размер и содержимое файла независимо от ограничений интерфейса.

10. Изображения и медиа

HTML предоставляет встроенные средства для работы с изображениями, аудио и видео без сторонних плагинов.

10.1. Изображения

<img src="photo.jpg" alt="Описание фотографии" width="800" height="600" loading="lazy">

Атрибут alt обязателен: он описывает изображение для пользователей, которые не могут его увидеть. Атрибуты width и height помогают браузеру заранее зарезервировать место и избежать сдвигов макета. Атрибут loading="lazy" откладывает загрузку изображений, пока они не приблизятся к области просмотра.

<picture>
  <source srcset="photo-large.webp" type="image/webp">
  <source srcset="photo-large.jpg" type="image/jpeg">
  <img src="photo-fallback.jpg" alt="Описание">
</picture>

Элемент picture позволяет выбрать подходящий формат или вариант изображения в зависимости от поддержки браузером и условий отображения.

10.2. Аудио и видео

<audio controls>
  <source src="sound.mp3" type="audio/mpeg">
  <source src="sound.ogg" type="audio/ogg">
  Браузер не поддерживает встроенное аудио.
</audio>

<video controls width="640" poster="preview.jpg">
  <source src="movie.mp4" type="video/mp4">
  <source src="movie.webm" type="video/webm">
  <track kind="subtitles" src="subs_ru.vtt" srclang="ru" label="Русские">
  Браузер не поддерживает встроенное видео.
</video>

Атрибут controls добавляет стандартные элементы управления. Атрибут poster задаёт изображение-превью для видео. Элемент track подключает субтитры, описания и другие дорожки в форматах WebVTT.

11. Встраиваемые ресурсы

HTML позволяет встраивать внешние документы, плагины и другие ресурсы.

ЭлементНазначение
iframeВстраивание другого HTML-документа.
embedВстраивание внешнего приложения или плагина.
objectУниверсальный контейнер для внешних ресурсов.
video, audioМультимедийные ресурсы.
svgВстроенная векторная графика.
mathВстроенные математические формулы (MathML).
<iframe src="https://example.com"
        width="600" height="400"
        title="Встроенный документ"
        sandbox="allow-scripts allow-same-origin"
        loading="lazy">
</iframe>

Атрибут sandbox ограничивает возможности встроенного документа. Разрешения можно добавлять точечно: allow-scripts, allow-same-origin, allow-forms и другие. Комбинация allow-scripts и allow-same-origin даёт встроенному документу возможность снять ограничения песочницы, поэтому её следует применять только к доверенному содержимому.

12. SVG, Canvas и MathML

HTML поддерживает встроенную векторную графику, программное рисование и математическую разметку.

12.1. SVG

<svg width="200" height="200" viewBox="0 0 200 200" role="img" aria-label="Круг">
  <circle cx="100" cy="100" r="80" fill="royalblue" />
</svg>

SVG описывает графику в виде XML-элементов. Он масштабируется без потери качества, поддерживает стили CSS, анимации и события. SVG подходит для иконок, диаграмм и иллюстраций.

12.2. Canvas

<canvas id="drawing" width="400" height="300"></canvas>
<script>
  const ctx = document.getElementById("drawing").getContext("2d");
  ctx.fillStyle = "royalblue";
  ctx.fillRect(50, 50, 100, 100);
</script>

Canvas предоставляет поверхность для программного рисования через JavaScript. Он подходит для игр, визуализаций данных и сложной графики, но не является семантическим содержимым документа.

12.3. MathML

<math xmlns="http://www.w3.org/1998/Math/MathML">
  <mrow>
    <msup><mi>a</mi><mn>2</mn></msup>
    <mo>+</mo>
    <msup><mi>b</mi><mn>2</mn></msup>
    <mo>=</mo>
    <msup><mi>c</mi><mn>2</mn></msup>
  </mrow>
</math>

MathML описывает математические формулы семантически. Вспомогательные технологии могут читать формулы, а браузеры отображают их с правильным форматированием. Поддержка MathML в браузерах развивается, и для сложных случаев иногда используют SVG или изображения с текстовыми альтернативами.

13. Встроенная интерактивность

HTML предоставляет элементы с встроенным поведением, которое не требует JavaScript для базовой работы.

ЭлементНазначение
details, summaryРаскрывающийся блок с заголовком.
dialogДиалоговое окно или модальный блок.
popover (атрибут)Всплывающий слой поверх содержимого.
select, datalistВыбор из списка вариантов.
progress, meterИндикаторы выполнения и измерения.
<details>
  <summary>Подробнее</summary>
  <p>Скрытое содержимое, которое раскрывается по клику.</p>
</details>

<dialog>
  <p>Это диалоговое окно.</p>
  <form method="dialog"><button>Закрыть</button></form>
</dialog>

<button popovertarget="tip">Показать подсказку</button>
<div id="tip" popover>Всплывающая подсказка.</div>

Элемент dialog можно открыть программно через методы showModal() или show(). Модальный диалог блокирует взаимодействие с остальной страницей. Атрибут popover создаёт всплывающий слой, который можно открыть через popovertarget или программно. Эти элементы предоставляют встроенное поведение без необходимости писать JavaScript.

14. Web Components

Web Components — набор браузерных API для создания переиспользуемых пользовательских элементов.

ТехнологияНазначение
Custom ElementsОпределение собственных HTML-элементов с поведением.
Shadow DOMИнкапсуляция DOM и стилей внутри элемента.
HTML TemplatesШаблоны разметки, которые не отображаются до активации.
SlotsМеханизм передачи содержимого в компонент.
class MyCard extends HTMLElement {
  constructor() {
    super();
    this.attachShadow({ mode: "open" });
    this.shadowRoot.innerHTML = `
      <style>
        :host { display: block; padding: 1rem; border: 1px solid #ccc; }
      </style>
      <slot>Содержимое по умолчанию</slot>
    `;
  }
}

customElements.define("my-card", MyCard);
<my-card>Пользовательское содержимое</my-card>

Web Components позволяют создавать компоненты, которые работают как обычные HTML-элементы. Shadow DOM изолирует стили и разметку компонента от остального документа. Это полезно для библиотек компонентов и виджетов, которые должны работать в разных контекстах без конфликтов стилей.

15. Метаданные и загрузка ресурсов

Элементы head и специальные атрибуты управляют тем, как браузер загружает и обрабатывает ресурсы.

15.1. Метаданные

<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<meta name="description" content="Описание страницы">
<meta name="theme-color" content="#3157c8">

<link rel="icon" href="favicon.ico">
<link rel="manifest" href="site.webmanifest">
<link rel="canonical" href="https://example.com/page">

Метаданные помогают поисковым системам, социальным сетям и браузерам понимать документ. Атрибут theme-color задаёт цвет интерфейса браузера на мобильных устройствах. Файл manifest описывает параметры веб-приложения для установки.

15.2. Загрузка скриптов

<script src="old.js"></script>
<script src="defer.js" defer></script>
<script src="async.js" async></script>
<script type="module" src="module.js"></script>
АтрибутПоведение
(обычный)Блокирует парсинг HTML, загружается и выполняется немедленно.
deferЗагружается параллельно, выполняется после разбора HTML в порядке появления.
asyncЗагружается параллельно, выполняется сразу после загрузки, порядок не гарантирован.
type="module"Загружается как ES-модуль, откладывается по умолчанию (как defer), поддерживает import/export.

15.3. Предзагрузка и предварительное подключение

<link rel="preload" href="font.woff2" as="font" type="font/woff2" crossorigin>
<link rel="prefetch" href="next-page.html">
<link rel="preconnect" href="https://api.example.com">
<link rel="dns-prefetch" href="https://cdn.example.com">

Resource hints помогают браузеру оптимизировать загрузку. preload указывает на критичные ресурсы, которые нужно загрузить рано. prefetch загружает ресурсы, которые могут понадобиться позже. preconnect устанавливает соединение с сервером заранее. dns-prefetch выполняет DNS-разрешение заранее.

16. Доступность и SEO

Доступность (accessibility) и поисковая оптимизация (SEO) тесно связаны: обе требуют семантической разметки, текстовых альтернатив и понятной структуры.

16.1. Доступность

  • Используй семантические элементы: button вместо div onclick, nav для навигации.
  • Добавляй alt к изображениям, label к полям форм.
  • Обеспечивай клавиатурную навигацию и видимый фокус.
  • Проверяй контраст текста и фона.
  • Используй ARIA только там, где нативной семантики недостаточно.
  • Тестируй со скринридерами и клавиатурой.
<button type="button" aria-label="Закрыть окно">×</button>

<label for="search">Поиск</label>
<input id="search" type="search" aria-describedby="search-help">
<small id="search-help">Введите запрос для поиска</small>

16.2. SEO

  • Используй один h1 на страницу и логическую иерархию заголовков.
  • Добавляй meta description с кратким описанием страницы.
  • Используй link rel="canonical" для указания канонического URL.
  • Создавай sitemap.xml и robots.txt.
  • Обеспечивай быструю загрузку и мобильную адаптивность.
  • Используй структурированные данные (Schema.org) для расширенного отображения в поиске.

17. Безопасность и ограничения

HTML-документы выполняются в контексте браузера, который применяет модель безопасности для защиты пользователей.

17.1. Same-Origin Policy

Браузер ограничивает взаимодействие между документами из разных источников (origin). Origin определяется схемой, хостом и портом. Например, https://example.com и https://api.example.com — разные origin.

17.2. Content Security Policy

Content-Security-Policy: default-src 'self'; script-src 'self' https://trusted.cdn.com

CSP ограничивает источники, из которых можно загружать скрипты, стили, изображения и другие ресурсы. Это снижает риск XSS-атак. Политика передаётся через HTTP-заголовок или meta-тег.

17.3. Subresource Integrity

<script src="https://cdn.example.com/lib.js"
        integrity="sha384-oqVuAfXRKap7fdgcCY5uykM6+R9GqQ8K/uxy9rx7HNQlGYl1kPzQho1wx4JwY8wC"
        crossorigin="anonymous"></script>

Атрибут integrity проверяет, что загруженный ресурс соответствует ожидаемому хэшу. Если файл был изменён, браузер не выполнит его. Это защищает от компрометации CDN.

17.4. Referrer Policy

<meta name="referrer" content="strict-origin-when-cross-origin">

Политика referrer управляет тем, какая информация о URL отправляется в заголовке Referer при переходе по ссылкам или загрузке ресурсов. Это важно для конфиденциальности.

18. Устаревшие элементы

Некоторые HTML-элементы устарели и не должны использоваться в новых документах. Они сохранены для обратной совместимости, но их функциональность заменена CSS или другими механизмами.

Устаревший элементСовременная замена
font, center, big, small (визуальное оформление)CSS для стилизации.
frame, framesetiframe или серверные шаблоны.
marquee, blinkCSS-анимации (если действительно нужны).
appletJava-апплеты больше не поддерживаются; используйте WebAssembly или JavaScript.
acronymabbr.

Использование устаревших элементов ухудшает доступность, семантику и совместимость с современными инструментами. Валидатор HTML предупредит о таких элементах.

19. Карта возможностей HTML

HTML предоставляет широкий набор возможностей для структурирования документа, форм, мультимедиа, графики и взаимодействия с браузером.

Структура и семантика

Заголовки, абзацы, списки, таблицы, секционные элементы, метаданные.

Формы и ввод

Поля ввода, валидация, отправка данных, файлы.

Мультимедиа

Изображения, аудио, видео, субтитры.

Графика

SVG, Canvas, MathML.

Интерактивность

Details, dialog, popover, встроенные контролы.

Компоненты

Безопасность

Sandbox, CSP, SRI, Referrer Policy.

Производительность

Lazy loading, preload, prefetch, preconnect.

20. Практика и источники

Лучший способ изучить HTML — создавать реальные документы и проверять их в браузере и валидаторе.

20.1. Практические задания

  1. Создай страницу с заголовком, навигацией, основным содержимым и подвалом. Используй семантические элементы.
  2. Добавь форму регистрации с разными типами полей и встроенной валидацией.
  3. Вставь изображение с alt, аудио и видео с субтитрами.
  4. Создай раскрывающийся блок с details и модальное окно с dialog.
  5. Проверь страницу в валидаторе W3C и исправь ошибки.
  6. Протестируй страницу с клавиатурой и скринридером.
