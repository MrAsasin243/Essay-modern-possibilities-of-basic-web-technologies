HTML: структура, смысл и содержимое страницы

HTML определяет, какие элементы присутствуют в документе, как они связаны между собой и какое значение имеют. Это не просто набор тегов: HTML задаёт семантическую структуру, предоставляет формы и встроенные элементы интерфейса, описывает мультимедиа и связывает документ с ресурсами.

1. Что такое HTML и за что он отвечает

HTML (HyperText Markup Language) — язык разметки гипертекста, используемый для описания структуры и семантики веб-документов.

HTML не является языком программирования общего назначения: в нём нет привычной модели произвольных вычислений, циклов и функций. Его задача — разметить содержимое документа так, чтобы браузер и другие программы могли определить, что представляет собой каждый фрагмент.

HTML

Структура и смысл: заголовки, абзацы, формы, ссылки, изображения.

CSS

Представление: цвета, типографика, размеры, сетки и адаптивность.

JavaScript

Поведение: алгоритмы, события, динамика и взаимодействие с API.

Важная оговорка. Это разделение описывает основные роли, но не является жёсткой границей. HTML уже содержит встроенное поведение некоторых элементов, CSS умеет создавать анимации и реагировать на состояния, а JavaScript может менять структуру и оформление документа.

Сегодня HTML развивается как Living Standard — живой стандарт, который обновляется непрерывно. Поэтому HTML5 — исторически распространённое название поколения HTML, а не отдельная современная версия, которую нужно выбирать в документе.

2. Как HTML обрабатывается браузером

Когда браузер получает HTML-документ, он запускает HTML-парсер. Парсер читает поток символов, разбирает разметку и формирует структуру документа. Разбор может продолжаться по мере получения данных из сети.

2.1. DOM — объектная модель документа

DOM (Document Object Model) — программное представление документа в виде дерева узлов и объектов. Браузер строит DOM при разборе HTML. JavaScript может читать и изменять эту структуру: добавлять элементы, менять текст и атрибуты, удалять узлы и подписываться на события.

<body>
  <h1>Мой сайт</h1>
  <p>Изучаю <strong>HTML</strong>.</p>
</body>
Document
└── html
    ├── head
    └── body
        ├── h1
        │   └── "Мой сайт"
        └── p
            ├── "Изучаю "
            └── strong
                └── "HTML"

Для живого примера нужен включённый JavaScript. Код и пояснения к нему показаны в блоках выше и ниже.

DOM не тождествен исходному HTML-файлу. Во время построения дерева браузер исправляет некоторые ошибки разметки по правилам HTML, а после загрузки JavaScript может изменить DOM. В результате текущее дерево может отличаться от текста, который пришёл с сервера.

Связь с будущим разделом JavaScript: методы вроде document.querySelector(), свойства textContent и методы append() работают с DOM, а не редактируют исходный HTML-файл на диске.

3. Синтаксис HTML

3.1. Элемент и тег

Элемент — единица документа, а теги — синтаксические конструкции, которыми обычно обозначают его начало и конец.

<p>Привет, мир!</p>
  • <p> — открывающий тег.
  • Привет, мир! — текстовое содержимое.
  • </p> — закрывающий тег.
  • Вся конструкция — элемент абзаца.

Элементы могут вкладываться друг в друга. Вложенность должна соответствовать правилам содержимого HTML.

<div>
  <h1>Заголовок</h1>
  <p>Текст с <strong>выделением</strong>.</p>
</div>

3.2. Атрибуты

Атрибуты задают элементу дополнительные параметры. Обычно они указываются в открывающем теге в форме имя="значение".

<a href="https://example.com" target="_blank">
  Открыть сайт
</a>

Здесь href задаёт адрес ссылки, а target — контекст её открытия.

Распространённые глобальные атрибуты

АтрибутНазначение
idИдентификатор элемента в пределах документа; обычно должен быть уникальным.
classНабор имён классов для группировки элементов и выбора их в CSS или JavaScript.
styleВстроенное CSS-описание оформления конкретного элемента.
titleДополнительная подсказка или пояснение.
langЯзык содержимого элемента.
dirНаправление текста: например, слева направо или справа налево.
hiddenУказывает, что элемент не должен отображаться обычным образом.
tabindexВключает элемент в клавиатурную навигацию и задаёт его порядок фокуса.
contenteditableРазрешает редактирование содержимого пользователем.
draggableУчаствует ли элемент в механизме перетаскивания.
data-*Пользовательские данные, связанные с конкретным элементом.
aria-*Дополнительная семантическая информация для вспомогательных технологий.
<div id="profile" class="user-card active"
     data-user-id="125">
  Профиль пользователя
</div>

3.3. Пустые элементы

Некоторые элементы не могут содержать дочерние узлы и не имеют закрывающего тега. Их называют void elements.

<img src="photo.jpg" alt="Фотография">
<br>
<hr>
<input type="text">
<meta charset="UTF-8">

В HTML не нужно записывать для них отдельные закрывающие теги. Косая черта перед > не превращает обычный HTML в XML.

3.4. Комментарии и символьные ссылки

<!-- Комментарий: браузер не показывает его как обычный текст -->

<p>5 &lt; 10</p>
<p>HTML &amp; CSS</p>
<p>&copy; 2026</p>

Символьные ссылки нужны, чтобы записывать зарезервированные символы и специальные знаки. Например, &lt; отображается как знак «меньше».

3.5. Вложенность и восстановление ошибок

Браузеры пытаются восстановить документ при многих синтаксических ошибках, однако результат восстановления не всегда совпадает с намерением автора.

<!-- Некорректная вложенность -->
<p>Первый абзац
  <p>Второй абзац</p>
</p>

<!-- Корректная запись -->
<p>Первый абзац</p>
<p>Второй абзац</p>

4. Каркас HTML-документа

Ниже — типичная основа HTML-страницы. Она подходит для большинства обычных документов.

<!doctype html>
<html lang="ru">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Моя страница</title>
  <meta name="description" content="Краткое описание страницы">
  <link rel="stylesheet" href="styles.css">
  <script src="app.js" defer></script>
</head>
<body>
  <h1>Заголовок страницы</h1>
  <p>Содержимое документа.</p>
</body>
</html>
ЧастьНазначение
<!doctype html>Объявляет HTML-документ и включает стандартный режим отображения браузера.
<html>Корневой элемент. Атрибут lang сообщает основной язык документа.
<head>Метаданные, название, ссылки на ресурсы и настройки документа.
<body>Основное содержимое, предназначенное для документа.

4.1. Назначение важных элементов head

  • meta charset="utf-8" — указывает кодировку документа.
  • meta name="viewport" — задаёт параметры области просмотра, особенно важные для мобильных устройств.
  • title — название документа, используемое во вкладке и другими системами.
  • meta name="description" — краткое описание страницы; его использование поисковиком зависит от контекста.
  • link rel="stylesheet" — подключает внешнюю таблицу стилей.
  • script — подключает или содержит сценарий.
Не путай: содержимое head — не «скрытый блок страницы». Это область метаданных. Большинство обычного видимого содержимого размещают в body.

5. Структура и семантика документа

Семантика — это смысловое назначение элемента. Например, <nav> обозначает навигационную область, а <main> — основное содержимое документа.

ЭлементНазначение
headerВводная или заголовочная часть страницы либо раздела.
navОбласть с основными навигационными ссылками.
mainОсновное уникальное содержимое страницы.
articleСамостоятельный материал, который может существовать отдельно: статья, публикация, карточка новости.
sectionТематически объединённый раздел, обычно с заголовком.
asideДополнительное содержимое, связанное с основным или окружающим разделом.
footerЗаключительная часть страницы или раздела.
addressКонтактная информация для ближайшего подходящего раздела или документа.
divУниверсальный контейнер без собственной семантики.
spanУниверсальный строчный контейнер без собственной семантики.
<body>
  <header>
    <h1>Новости технологий</h1>
  </header>

  <nav aria-label="Основная навигация">
    <a href="/">Главная</a>
    <a href="/articles">Статьи</a>
  </nav>

  <main>
    <article>
      <h2>Новая публикация</h2>
      <p>Текст статьи...</p>
    </article>
    <aside>Связанные материалы</aside>
  </main>

  <footer>Контактная информация</footer>
</body>

Для живого примера нужен включённый JavaScript. Код и пояснения к нему показаны в блоках выше и ниже.

Семантическая разметка помогает вспомогательным технологиям и программам понимать структуру. Она также упрощает сопровождение кода. Визуальное оформление само по себе не делает элемент семантическим: div, стилизованный как заголовок, всё равно остаётся обычным контейнером.

7. Гиперссылки и навигация

Гиперссылки связывают документы и ресурсы — это одна из основ гипертекста. Основной элемент — <a>. Атрибут href задаёт адрес назначения.

<!-- Внешний ресурс -->
<a href="https://example.com">Открыть сайт</a>

<!-- Новая вкладка -->
<a href="https://example.com" target="_blank" rel="noopener">
  Открыть в новой вкладке
</a>

<!-- Переход к элементу с id="contacts" -->
<a href="#contacts">Контакты</a>

<!-- Почтовый адрес и телефонный URI -->
<a href="mailto:hello@example.com">Написать</a>
<a href="tel:+358123456789">Позвонить</a>

<!-- Подсказка браузеру скачать ресурс -->
<a href="guide.pdf" download>Скачать PDF</a>

Для живого примера нужен включённый JavaScript. Код и пояснения к нему показаны в блоках выше и ниже.

URL может быть абсолютным или относительным. Относительные адреса вычисляются относительно адреса документа и, при наличии, элемента <base>. Атрибут target="_blank" открывает ссылку в новом browsing context; для внешних ссылок полезно явно задавать подходящий rel и продумывать пользовательский опыт.

8. Таблицы

Таблицы предназначены для данных, где есть отношения между строками и столбцами. Не следует использовать их вместо CSS Grid или Flexbox для компоновки всей страницы.

theadГруппа строк заголовка.
tbodyОсновная группа строк.
tfootНижняя группа строк, например итоги.
trСтрока.
thЗаголовочная ячейка.
tdЯчейка данных.
colgroup, colОписание столбцов или групп столбцов.

  <thead>
    <tr><th scope="col">Студент</th><th scope="col">Математика</th></tr>
  </thead>
  <tbody>
    <tr><th scope="row">Алексей</th><td>5</td></tr>
    <tr><th scope="row">Иван</th><td>4</td></tr>
  </tbody>
</table>

Для живого примера нужен включённый JavaScript. Код и пояснения к нему показаны в блоках выше и ниже.

Для доступности таблиц важно правильно связывать заголовки с ячейками. Для простых таблиц обычно достаточно th и scope; для сложных структур могут понадобиться более точные связи.

9.2. Пример формы

<form action="/register" method="post">
  <label for="email">Электронная почта</label>
  <input id="email" name="email" type="email" required>

  <label for="age">Возраст</label>
  <input id="age" name="age" type="number" min="18" max="100" required>

  <button type="submit">Зарегистрироваться</button>
</form>

У form важны атрибуты action (адрес обработчика), method (метод запроса), enctype (кодирование тела запроса). У полей важен атрибут name: именно по нему формируются имена отправляемых значений.

Безопасность: клиентская валидация улучшает удобство, но не защищает сервер. Запрос можно сформировать вручную, поэтому сервер обязан повторно проверять тип, формат, диапазоны, права доступа и допустимость каждого значения.

  <button type="submit">Загрузить</button>

Для файловой отправки обычно используют POST и multipart/form-data. Сервер должен проверять размер и содержимое файла независимо от ограничений интерфейса.

10. Изображения, аудио и видео

10.1. Изображения

Ключевые атрибуты: src — ресурс изображения; alt — текстовая альтернатива; width и height — геометрические размеры; loading="lazy" — отложенная загрузка, когда это уместно; decoding — подсказка браузеру о декодировании.

Адаптивные изображения

picture, source, srcset и sizes позволяют указать несколько вариантов, чтобы браузер выбрал подходящий ресурс по условиям отображения и характеристикам экрана.

  <img src="large.jpg" alt="Горный пейзаж">
</picture>

<img
  src="photo-800.jpg"
  srcset="photo-400.jpg 400w, photo-800.jpg 800w, photo-1600.jpg 1600w"
  sizes="(max-width: 600px) 100vw, 800px"

>

11. Встраивание внешних ресурсов

11.1. iframe

iframe создаёт вложенный browsing context, в котором отображается другой HTML-документ. Его применяют для карт, видеоплееров, внешних виджетов и изолированных частей интерфейса.

<iframe
  src="https://example.com/widget"
  title="Встроенный виджет"
  width="800"
  height="500"
  loading="lazy"
  referrerpolicy="strict-origin-when-cross-origin"
></iframe>

Для безопасности могут использоваться атрибуты sandbox и allow. Они ограничивают или разрешают отдельные возможности вложенной страницы. Взаимодействие документов также ограничено политикой одного источника (Same-Origin Policy).

Для живого примера нужен включённый JavaScript. Код и пояснения к нему показаны в блоках выше и ниже.

11.2. Другие элементы

  • object — встраивание внешнего ресурса с возможностью резервного содержимого.
  • embed — встраивание внешнего содержимого; его практическое применение сегодня ограничено.
  • source — альтернативные источники для мультимедиа и изображений.
  • track — текстовые дорожки, например субтитры и описания.
Встраивание другого документа не означает, что родительская страница получает полный доступ к его DOM. Для безопасной коммуникации между разными источниками применяется, например, postMessage() с проверкой источника сообщения.

12. Графика и математическая разметка: SVG, Canvas и MathML

HTML позволяет встраивать графическое и математическое содержимое. При этом SVG, Canvas API и MathML — отдельные технологии или интерфейсы, интегрированные с веб-документом.

12.1. SVG — векторная графика

SVG (Scalable Vector Graphics) описывает графику через геометрические объекты, пути, текст, заливки и другие векторные конструкции. SVG можно встроить прямо в HTML.

<svg viewBox="0 0 300 160" role="img" aria-label="Прямоугольник и окружность">
  <rect x="15" y="20" width="120" height="90" rx="8" fill="#3157c8"></rect>
  <circle cx="220" cy="65" r="45" fill="#e49a32"></circle>
</svg>

SVG хорошо подходит для иконок, логотипов, схем, диаграмм и интерактивной векторной графики. Его объекты представлены в DOM и могут иметь собственные атрибуты и обработчики событий.

Для живого примера нужен включённый JavaScript. Код и пояснения к нему показаны в блоках выше и ниже.

12.2. Canvas — программное рисование

<canvas> задаёт область для рисования. Сам HTML создаёт поверхность, а рисование выполняется через JavaScript API, например Canvas 2D, или графические API вроде WebGL.

<canvas id="scene" width="400" height="220">
  Альтернативное описание графики.
</canvas>

<script>
  const canvas = document.querySelector("#scene");
  const context = canvas.getContext("2d");
  context.fillStyle = "steelblue";
  context.fillRect(30, 30, 180, 100);
</script>

Canvas подходит для игр, визуализаций, симуляций и задач, где нужно часто перерисовывать большое количество графических объектов. Отдельные нарисованные фигуры сами по себе не становятся HTML-узлами DOM, поэтому интерактивность и доступность нужно продумывать отдельно.

Для живого примера нужен включённый JavaScript. Код и пояснения к нему показаны в блоках выше и ниже.

12.3. MathML — математическая разметка

MathML описывает математические выражения в структурированной форме, чтобы браузер и вспомогательные технологии могли интерпретировать формулу, а не воспринимать её просто как картинку.

<math>
  <msup><mi>x</mi><mn>2</mn></msup>
  <mo>+</mo>
  <msup><mi>y</mi><mn>2</mn></msup>
  <mo>=</mo>
  <msup><mi>z</mi><mn>2</mn></msup>
</math>

Для живого примера нужен включённый JavaScript. Код и пояснения к нему показаны в блоках выше и ниже.

ТехнологияМодельТипичные задачи

13. Встроенная интерактивность HTML

Не вся интерактивность требует JavaScript. Некоторые элементы имеют стандартное поведение, реализованное браузером.

13.1. Раскрывающийся блок

<details>
  <summary>Показать пояснение</summary>
  <p>Дополнительный текст.</p>
</details>

Браузер обеспечивает открытие и закрытие содержимого. Для базового disclosure-компонента собственный сценарий не нужен.

Живой пример · работает без JavaScript

Показать пояснение

Браузер сам открывает и сворачивает блок. Клавиши Enter и пробел работают на заголовке summary, фокус и доступность встроены.

Группа: первый пункт

В группе с одинаковым атрибутом name одновременно может быть открыт только один блок.

Группа: второй пункт

Если браузер не поддерживает name у details, блоки будут работать независимо, и это безопасная деградация.

Подводные камни: содержимое закрытого блока остаётся в DOM, но не показывается, а поиск по странице и переход по якорю внутрь закрытого блока раскрывают его не во всех браузерах одинаково; нельзя анимировать высоту details без дополнительных приёмов; атрибут name появился относительно недавно.

13.2. Диалоговое окно

<dialog id="confirm-dialog">
  <h2>Подтверждение</h2>
  <p>Продолжить операцию?</p>
  <form method="dialog">
    <button value="cancel">Отмена</button>
    <button value="confirm">Подтвердить</button>
  </form>
</dialog>

<script>
  document.querySelector("#confirm-dialog").showModal();
</script>

HTML задаёт диалоговую структуру, а методы show() и showModal() относятся к API элемента, доступному через JavaScript. Модальный диалог получает специальное поведение, включая управление фокусом и закрытие клавишей Escape в стандартном сценарии.

Для живого примера нужен включённый JavaScript. Код и пояснения к нему показаны в блоках выше и ниже.

13.3. Popover API

<button popovertarget="help-panel">Показать подсказку</button>
<div id="help-panel" popover>
  Дополнительная информация.
</div>

Атрибут popover совместно с popovertarget позволяет реализовать простой всплывающий элемент без собственного JavaScript для базового открытия и закрытия.

Живой пример · Popover API без JavaScript

Дополнительная информация. Закрывается клавишей Esc или кликом вне панели (light dismiss), а фокус возвращается на кнопку.

Подводные камни: без поддержки браузера атрибут popover игнорируется и панель просто видна на странице; popover не блокирует остальной интерфейс и не подходит вместо модального диалога; позиционирование относительно кнопки требует CSS anchor positioning, поддержка которого пока ограничена; одновременно открытый «ручной» popover (popover="manual") нужно закрывать самостоятельно; все popover попадают в верхний слой, где z-index не работает.

13.4. Другие возможности

  • contenteditable — редактирование содержимого пользователем.
  • inert — исключение поддерева из обычного взаимодействия и последовательности фокуса.
  • tabindex — включение элемента в клавиатурную навигацию.
  • draggable — участие в HTML Drag and Drop.
  • autofocus — запрос фокуса на элементе при загрузке или показе соответствующего интерфейса.

Для живого примера нужен включённый JavaScript. Код и пояснения к нему показаны в блоках выше и ниже.

Эти механизмы имеют ограничения и особенности. Например, наличие draggable не создаёт готовый файловый менеджер, а contenteditable не является полноценным текстовым редактором.

15. Метаданные и управление загрузкой ресурсов

15.1. Метаданные и связи

  • title — заголовок документа.
  • meta — кодировка, описание, viewport и другие метаданные.
  • link — связь документа с внешним ресурсом или документом.
  • base — базовый URL для относительных адресов и контекст по умолчанию для ссылок.
  • style — таблица CSS внутри документа.
  • script — встроенный сценарий или ссылка на него.
  • noscript — альтернативное содержимое, когда сценарии недоступны или отключены.

15.2. Режимы подключения скриптов

ЗаписьОбщее поведение
<script src="app.js">Обычный классический скрипт при разборе документа может приостановить парсер, пока не загрузится и не выполнится.
deferКлассический внешний скрипт загружается параллельно с разбором HTML и выполняется после завершения разбора; порядок таких скриптов сохраняется.
asyncВнешний скрипт загружается параллельно и выполняется, когда готов; порядок выполнения нескольких async-скриптов не гарантируется.
type="module"Подключает JavaScript-модуль; модули по умолчанию откладываются до завершения разбора документа, если не задано иное поведение.

15.3. Подсказки загрузчику ресурсов

Элементы link с различными значениями rel позволяют сообщить браузеру о предполагаемом использовании ресурсов.

  • preload — ресурс нужен текущей странице и может быть загружен заранее.
  • prefetch — ресурс может понадобиться в будущем.
  • preconnect — заранее начать установление соединения с источником.
  • dns-prefetch — заранее выполнить разрешение доменного имени.
  • icon — указать иконку сайта.
  • canonical — сообщить предпочтительный URL документа поисковым системам.
<link rel="icon" href="/favicon.ico">
<link rel="preconnect" href="https://cdn.example.com">
<link rel="preload" href="/fonts/site.woff2" as="font" type="font/woff2" crossorigin>
<script src="app.js" defer></script>

Подсказки загрузки нужно использовать осмысленно: избыточные preload/preconnect могут ухудшить приоритеты загрузки и расходовать сетевые ресурсы.

16.2. ARIA

ARIA (Accessible Rich Internet Applications) — набор атрибутов для уточнения роли, состояния и свойств интерфейса для вспомогательных технологий. ARIA полезна, когда нативной семантики недостаточно, но не должна заменять подходящий HTML-элемент.

16.3. SEO и структурированные данные

HTML помогает поисковым системам понять заголовки, ссылки, основной материал, язык и метаданные документа. Для более формального описания сущностей используют структурированные данные, например JSON-LD. Наличие разметки не гарантирует определённое место в поисковой выдаче или специальный сниппет.

17. Безопасность и границы HTML

HTML участвует в безопасности веб-приложения, но сам по себе не заменяет серверную защиту и политики браузера.

  • Валидация форм: помогает пользователю, но сервер повторно проверяет все входящие данные.
  • iframe sandbox: ограничивает возможности встроенного документа; набор разрешений нужно выбирать осторожно.
  • Внешние ссылки: при открытии новых вкладок учитывают безопасность и ожидаемое поведение пользователя.
  • Вывод пользовательского HTML: нельзя без очистки вставлять недоверенную разметку как доверенное содержимое.
  • Политики безопасности: Content Security Policy и другие механизмы браузера обычно настраиваются HTTP-заголовками или метатегами в поддерживаемых случаях.

20. Практика и авторитетные источники

20.1. Практическая последовательность

  1. Создай простой документ с корректным каркасом doctype, html, head и body.
  2. Собери семантическую страницу: шапка, навигация, основное содержимое, статья и подвал.
  3. Добавь заголовки, списки, ссылки, изображения и таблицу с заголовочными ячейками.
  4. Создай форму регистрации с подписями, несколькими типами полей и встроенной валидацией.
  5. Добавь аудио или видео с альтернативным содержимым и субтитрами.
  6. Попробуй встроить SVG, создать Canvas-поверхность и добавить раскрывающийся блок details.
  7. Проверь разметку валидатором и пройди страницу клавиатурой без мыши.
