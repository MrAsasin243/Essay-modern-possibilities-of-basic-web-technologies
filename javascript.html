JavaScript: язык программирования веба

От базового синтаксиса до построения динамических приложений: разберём сам язык, модель выполнения, DOM, события, сеть, хранилища и интерфейсы браузера.

1. Что такое JavaScript

JavaScript (JS) — динамический мультипарадигменный язык программирования. Он позволяет описывать вычисления, преобразование данных, правила работы приложения и реакцию программы на события.

В веб-разработке JavaScript чаще всего запускается в браузере. Он может читать и изменять DOM, обрабатывать действия пользователя, отправлять запросы на сервер, хранить данные на клиенте и обращаться к возможностям устройства через Web API.

Императивный стиль

Программист описывает последовательность команд и изменение состояния.

Объектный стиль

Данные и поведение можно организовывать вокруг объектов, прототипов и классов.

Функциональный стиль

Функции можно передавать как значения, комбинировать и использовать для преобразования данных.

Что JavaScript делает на странице

  • Реагирует на нажатия, ввод текста, прокрутку, перетаскивание и другие события.
  • Изменяет содержимое и структуру страницы через DOM.
  • Проверяет данные форм и показывает ошибки пользователю.
  • Получает и отправляет данные через сеть.
  • Создаёт интерактивные графики, редакторы, игры и сложные интерфейсы.
  • Использует браузерные API: хранилища, геолокацию, мультимедиа, уведомления и другие возможности.
Важно: JavaScript и Java — разные языки. Сходство названий историческое и не означает, что это варианты одной технологии.

3. Подключение JavaScript к HTML

Код можно разместить в HTML-документе или подключить отдельным файлом. Для реального проекта обычно удобнее внешние файлы: код разделён по назначению, его проще обслуживать и кэшировать.

Встроенный сценарий

<script>
  console.log("Страница загружена");
</script>

Внешний файл

<script src="app.js" defer></script>

Как отличаются режимы загрузки

deferЗагрузка идёт параллельно разбору HTML; выполнение — после разбора документа, с сохранением порядка таких скриптов.Обычные внешние скрипты, которым нужен уже разобранный документ.

Не путай: defer и async — не режимы самого языка. Это атрибуты HTML-элемента script, влияющие на загрузку и выполнение сценария браузером.

4. Синтаксис и базовые правила

Инструкции и выражения

Выражение вычисляется в значение. Инструкция организует выполнение действия или последовательности действий.

2 + 3                 // выражение: значение 5
const total = 2 + 3;  // объявление переменной — инструкция
console.log(total);  // вызов функции как инструкция

Комментарии

// Однострочный комментарий

/*
  Многострочный
  комментарий
*/

Точка с запятой

В JavaScript действует автоматическая вставка точек с запятой (ASI), но она не делает любые переносы строк безопасными. В командах проекта следует придерживаться единого стиля форматирования и явно ставить точки с запятой либо последовательно использовать выбранное соглашение.

Строгий режим

"use strict";

// В строгом режиме некоторые ошибочные или неоднозначные
// конструкции вызывают исключения вместо тихого поведения.

Код JavaScript-модуля автоматически выполняется в строгом режиме. В классических сценариях строгий режим можно включить директивой в начале скрипта или функции.

Имена и регистр

Имена чувствительны к регистру: userName и username — разные идентификаторы. Имя не может начинаться с цифры, а зарезервированные ключевые слова нельзя использовать как обычные имена переменных.

5. Переменные и область видимости

Переменная связывает имя со значением. В современном JavaScript в основном используются const и let.

const siteName = "Web Guide"; // нельзя переназначить
let pageViews = 0;             // можно переназначить
pageViews += 1;

var legacyValue = 10;          // старый способ объявления
ОбъявлениеПовторное объявление в той же областиОбласть видимостиОсобенности
constНетБлочнаяНужно сразу присвоить начальное значение; нельзя переназначить переменную.
letНетБлочнаяМожно переназначать значение.
varДа, в пределах допустимых правилФункциональная или глобальнаяИмеет исторические особенности поднятия объявления и взаимодействия с глобальным объектом.

const запрещает переназначить саму переменную, но не делает объект или массив неизменяемым.

const user = { name: "Алексей" };
user.name = "Иван";       // допустимо
// user = {};              // TypeError: переназначение запрещено

Область видимости

Область видимости (scope) определяет, из каких частей программы доступно имя. Основные виды: глобальная, функциональная и блочная.

const globalValue = "видно снаружи";

function example() {
  const functionValue = "видно внутри функции";

  if (true) {
    const blockValue = "видно только в блоке";
    console.log(blockValue);
  }

  // console.log(blockValue); // ReferenceError
}

Поднятие (hoisting) и временная мёртвая зона

Объявления обрабатываются до выполнения соответствующего кода, но это не означает, что все переменные можно безопасно использовать до строки объявления. Для let и const до инициализации действует временная мёртвая зона (TDZ).

console.log(value); // ReferenceError
let value = 5;

JavaScript — динамически типизированный язык: тип связан со значением, а одна и та же переменная в разные моменты может содержать значения разных типов.

Примитивы и объекты: копирование

При присваивании примитивного значения переменная получает само значение. При присваивании объекта копируется ссылка на объект.

let a = 10;
let b = a;
b = 20;
console.log(a); // 10

const first = { score: 5 };
const second = first;
second.score = 9;
console.log(first.score); // 9 — обе переменные обращаются к одному объекту

Проверка и преобразование типов

Number("42")       // 42
String(42)         // "42"
Boolean(0)         // false
Boolean("hello")  // true

Number("текст")   // NaN

Ложными (falsy) являются false, 0, -0, 0n, "", null, undefined и NaN. Практически все остальные значения истинны, в том числе пустой массив [] и пустой объект {}.

7. Операторы, сравнения и преобразования

Арифметические операторы

+, -, *, /, % (остаток), ** (возведение в степень), ++, --.

Сравнения

5 > 3          // true
5 >= 5         // true
5 === "5"      // false: типы различаются
5 == "5"       // true: произошло преобразование типов
5 !== "5"      // true

Обычно предпочтительны строгое равенство === и строгое неравенство !==, поскольку они не выполняют неявное приведение типов.

Логические операторы

  • && — логическое И с коротким замыканием.
  • || — логическое ИЛИ с коротким замыканием.
  • ! — логическое НЕ.
  • ?? — оператор нулевого слияния: берёт правую часть, только если левая равна null или undefined.
  • ?. — optional chaining: безопасный доступ при null или undefined.
const displayName = user.name ?? "Гость";
const city = user.address?.city;
const isReady = hasData && isValid;

Остальные полезные группы

Операторы присваивания (=, +=, ??=), побитовые операторы, условный оператор ? :, оператор распространения ..., оператор остаточных параметров, typeof, instanceof, in, delete, new, await и другие.

Оператор || выбирает правую часть для любого falsy-значения, а ?? — только для null и undefined. Для значений вроде нуля или пустой строки это принципиально важно.

8. Управление потоком выполнения

Управляющие конструкции определяют, какие команды будут выполнены, сколько раз и при каких условиях.

Условия

if (temperature > 25) {
  console.log("Жарко");
} else if (temperature < 10) {
  console.log("Холодно");
} else {
  console.log("Умеренная температура");
}

switch (status) {
  case "loading":
    console.log("Загрузка");
    break;
  case "success":
    console.log("Готово");
    break;
  default:
    console.log("Неизвестное состояние");
}

Циклы

for (let i = 0; i < 3; i++) {
  console.log(i);
}

while (condition) {
  // повторять, пока condition истинно
}

for (const item of items) {
  console.log(item); // значения итерируемого объекта
}

for (const key in object) {
  console.log(key); // перечисляемые ключи объекта
}

break завершает цикл или конструкцию switch, continue переходит к следующей итерации. Для массивов часто удобнее применять методы forEach, map, filter, find и другие — выбор зависит от задачи.

9. Функции, параметры и замыкания

Функция — значение, которое можно вызвать. Её можно сохранить в переменной, передать другой функции или вернуть из функции.

Функциональное объявление

function sum(a, b) {
  return a + b;
}

const result = sum(2, 3); // 5

Функциональное выражение и стрелочная функция

const multiply = function (a, b) {
  return a * b;
};

const square = (x) => x * x;
const greet = name => `Привет, ${name}`;
const createUser = () => ({ active: true });

Параметры по умолчанию и остаточные параметры

function greet(name = "Гость") {
  return `Здравствуйте, ${name}`;
}

function average(...numbers) {
  const total = numbers.reduce((sum, n) => sum + n, 0);
  return numbers.length === 0 ? 0 : total / numbers.length;
}

Область видимости и замыкание

Замыкание (closure) возникает, когда функция сохраняет доступ к лексическому окружению, в котором была создана, даже после завершения внешней функции.

function createCounter() {
  let count = 0;

  return function () {
    count += 1;
    return count;
  };
}

const counter = createCounter();
console.log(counter()); // 1
console.log(counter()); // 2

Для живого примера нужен включённый JavaScript. Код и пояснения показаны в блоках рядом.

Контекст this

В обычной функции значение this в основном определяется способом вызова. В стрелочной функции собственного this нет: она использует значение из окружающего лексического контекста.

const user = {
  name: "Ирина",
  sayName() {
    console.log(this.name);
  }
};

user.sayName(); // "Ирина"

const detached = user.sayName;
// detached(); // в строгом режиме this будет undefined

Для управления контекстом существуют call(), apply() и bind(). Понимание this, замыканий, областей видимости и передачи функций необходимо для работы с событиями, callbacks и асинхронным кодом.

10. Массивы, объекты-коллекции и итераторы

Массивы

const numbers = [1, 2, 3, 4];

numbers.push(5);                    // добавить в конец
numbers.pop();                      // удалить последний
const doubled = numbers.map(x => x * 2);
const even = numbers.filter(x => x % 2 === 0);
const first = numbers.find(x => x > 2);
const total = numbers.reduce((sum, x) => sum + x, 0);

const copy = [...numbers];          // поверхностная копия

Внимание: не все методы создают копию. Например, sort(), reverse() и splice() изменяют исходный массив. Для предсказуемой логики отслеживай, меняется ли исходная структура.

Map, Set, WeakMap и WeakSet

const scores = new Map();
scores.set("math", 95);
scores.set("physics", 88);
console.log(scores.get("math"));

const uniqueTags = new Set(["html", "css", "html"]);
console.log(uniqueTags.size); // 2
  • Map хранит пары ключ–значение; ключом может быть значение любого типа.
  • Set хранит уникальные значения.
  • WeakMap и WeakSet используют слабые ссылки на объекты и имеют ограничения на перечисление.

Другие структуры

Стандарт языка также включает строки и регулярные выражения, Date, RegExp, JSON, типизированные массивы, ArrayBuffer, DataView, итераторы и генераторы. Они нужны для текста, дат, двоичных данных и последовательной обработки значений.

11. Объекты, прототипы и классы

Создание объекта

const product = {
  id: 101,
  title: "Клавиатура",
  price: 4500,
  isAvailable: true,
  describe() {
    return `${this.title}: ${this.price} ₽`;
  }
};

console.log(product.title);
product.price = 4200;
product.category = "Периферия";

Свойства объекта можно читать, создавать, менять и удалять. Для доступа к свойству используются точка или квадратные скобки: object.name и object["name"].

Деструктуризация и spread

const { title, price } = product;
const updated = { ...product, price: 3990 };

const [first, second] = ["HTML", "CSS"];
const combined = [...[1, 2], 3, 4];

Spread создаёт поверхностную копию. Вложенные объекты по-прежнему могут ссылаться на те же значения.

Прототипное наследование

У объектов есть внутренний прототип. При обращении к отсутствующему собственному свойству JavaScript может искать его выше по цепочке прототипов. Это основа наследования в языке.

const animal = {
  speak() {
    console.log("Звук");
  }
};

const dog = Object.create(animal);
dog.bark = () => console.log("Гав");
dog.speak(); // метод найден в прототипе

Для живого примера нужен включённый JavaScript. Код и пояснения показаны в блоках рядом.

Классы

class User {
  constructor(name) {
    this.name = name;
  }

  introduce() {
    return `Меня зовут ${this.name}`;
  }
}

class Admin extends User {
  deletePost() {
    console.log("Публикация удалена");
  }
}

const admin = new Admin("Алексей");
console.log(admin.introduce());

Синтаксис class предоставляет удобную форму для работы с прототипным механизмом, а не отдельную от него модель объектов. Классы поддерживают конструкторы, методы, статические члены, геттеры/сеттеры, наследование и приватные поля с префиксом #.

12. Ошибки и исключения

Ошибки — ожидаемая часть разработки. Их нужно обнаруживать, классифицировать и обрабатывать там, где программа может восстановить нормальную работу или показать пользователю понятное сообщение.

try {
  const data = JSON.parse('{ invalid json }');
  console.log(data);
} catch (error) {
  console.error("Не удалось разобрать JSON:", error.message);
} finally {
  console.log("Этот блок выполнится в любом случае");
}

Для генерации исключения применяется throw. Существуют встроенные виды ошибок: Error, TypeError, RangeError, ReferenceError, SyntaxError и другие.

function divide(a, b) {
  if (b === 0) {
    throw new RangeError("Деление на ноль запрещено");
  }
  return a / b;
}

Не следует без разбора перехватывать все исключения и игнорировать их. Обработка должна либо исправлять ожидаемую ситуацию, либо добавлять контекст и передавать ошибку дальше.

13. Модули и организация файлов

Модуль позволяет разбить программу на файлы с явными зависимостями. Модуль экспортирует значения и импортирует то, что использует.

// math.js
export function add(a, b) {
  return a + b;
}

export const PI = Math.PI;

// app.js
import { add, PI } from "./math.js";
console.log(add(2, 3), PI);

В HTML модуль подключается так:

<script type="module" src="./app.js"></script>

Основные возможности

  • Именованные экспорты и импорты.
  • Экспорт по умолчанию (default).
  • Переименование импортируемых значений через as.
  • Динамический импорт через import(), возвращающий Promise.
  • Top-level await в ES-модулях.
  • Изоляция верхнеуровневых имён модуля от глобальной области.

В реальных проектах модули часто объединяются сборщиками или обрабатываются инструментами разработки. Но браузеры также умеют загружать ES-модули непосредственно.

Распространение события

События, поддерживающие bubbling, проходят фазы захвата (capture), достижения цели (target) и всплытия (bubble). Это позволяет обработчику на родительском элементе реагировать на события дочерних элементов.

  const item = event.target.closest("li");
  if (!item) return;

  console.log("Выбран пункт:", item.textContent);
});

Этот приём называется делегированием событий. Он удобен для динамически создаваемых списков: не нужно устанавливать обработчик на каждый дочерний элемент.

  • event.currentTarget — элемент, на котором сейчас выполняется обработчик.
  • preventDefault() — отменяет действие браузера по умолчанию, если оно отменяемое.
  • stopPropagation() — останавливает дальнейшее распространение события.
  • once, capture, passive, signal — опции обработчика.

17. Асинхронность, Promise и Event Loop

Обычный синхронный код выполняется последовательно. Но веб-приложения постоянно ждут внешние события: ответы сервера, таймеры, пользовательский ввод, чтение файлов и завершение других операций. Асинхронность позволяет не блокировать выполнение программы на всё время ожидания.

Callback

setTimeout(() => {
  console.log("Прошла секунда");
}, 1000);

Promise

Promise представляет будущее завершение асинхронной операции. Он находится в состоянии pending, затем становится fulfilled или rejected.

const promise = new Promise((resolve, reject) => {
  const success = true;

  if (success) {
    resolve("Операция завершилась");
  } else {
    reject(new Error("Операция не удалась"));
  }
});

promise
  .then(value => console.log(value))
  .catch(error => console.error(error))
  .finally(() => console.log("Завершение"));

async и await

async function loadProfile() {
  try {
    const response = await fetch("/api/profile");

    if (!response.ok) {
      throw new Error(`HTTP ${response.status}`);
    }

    const profile = await response.json();
    return profile;
  } catch (error) {
    console.error("Не удалось загрузить профиль:", error);
    throw error;
  }
}

Функция с async всегда возвращает Promise. await приостанавливает продолжение этой async-функции до завершения Promise, но не блокирует весь поток выполнения JavaScript.

Event Loop: упрощённая модель

Основные термины:

  • Call stack — стек текущих вызовов.
  • Task (macrotask в распространённой терминологии) — работа, например обработчик события или задача таймера.
  • Microtask — задача с более высоким приоритетом в соответствующей точке цикла; сюда относятся реакции Promise и MutationObserver.
  • Run-to-completion — текущая задача выполняется до завершения, прежде чем будет начата следующая задача в том же агенте.
console.log("A");

setTimeout(() => console.log("B: task"), 0);
Promise.resolve().then(() => console.log("C: microtask"));

console.log("D");
// Порядок: A, D, C: microtask, B: task

Для живого примера нужен включённый JavaScript. Код и пояснения показаны в блоках рядом.

Производительность: длинный синхронный цикл на главном потоке мешает обработке ввода и обновлению интерфейса. Асинхронное ожидание помогает с I/O, но само по себе не делает тяжёлые вычисления параллельными. Для таких вычислений могут использоваться Web Workers.

18. Сеть: HTTP, Fetch API, JSON и WebSocket

JavaScript в браузере может обмениваться данными с сервером. Типичный сценарий: отправить запрос, получить ответ, проверить статус, разобрать данные и обновить интерфейс.

Fetch API

async function loadUsers() {
  const response = await fetch("/api/users");

  // fetch не считает HTTP 404/500 автоматическим отказом Promise
  if (!response.ok) {
    throw new Error(`Ошибка сервера: ${response.status}`);
  }

  const users = await response.json();
  return users;
}

Fetch API работает с объектами Request и Response. Ответ можно читать как JSON, текст, Blob, ArrayBuffer, FormData и другими способами.

CORS и Same-Origin Policy

Политика одного источника (Same-Origin Policy) ограничивает доступ страницы к данным другого источника. CORS — механизм, с помощью которого сервер может явно разрешить браузеру предоставить странице доступ к определённому междоменному ответу.

Важно: CORS настраивается ответами сервера. Добавление произвольного заголовка в браузерный JavaScript не позволяет обойти эту защиту. Режим no-cors не превращает ответ в доступный для чтения: он, как правило, даёт непрозрачный Response.

Другие сетевые технологии

  • XMLHttpRequest — более старый API сетевых запросов; всё ещё используется в некоторых проектах.
  • WebSocket — двустороннее постоянное соединение для обмена сообщениями в реальном времени.
  • Server-Sent Events (EventSource) — поток событий от сервера к клиенту.
  • WebRTC — обмен аудио, видео и данными между участниками, часто напрямую между браузерами.
  • WebTransport — современный транспортный API для определённых сценариев низкой задержки; поддержка и условия использования зависят от браузеров и сервера.
const socket = new WebSocket("wss://example.com/socket");

socket.addEventListener("open", () => {
  socket.send(JSON.stringify({ type: "hello" }));
});

socket.addEventListener("message", event => {
  console.log("Сообщение:", event.data);
});

21. Web Workers и фоновые задачи

Основной поток браузера обрабатывает JavaScript страницы и тесно связан с пользовательским интерфейсом. Тяжёлая синхронная работа в нём может привести к зависанию интерфейса.

Dedicated Worker

Web Worker выполняет JavaScript в отдельном агенте/потоке без прямого доступа к DOM. Обмен данными с основным потоком происходит через сообщения.

// main.js
const worker = new Worker("worker.js", { type: "module" });
worker.postMessage({ numbers: [1, 2, 3, 4] });

worker.addEventListener("message", event => {
  console.log("Сумма:", event.data);
});

// worker.js
self.addEventListener("message", event => {
  const sum = event.data.numbers.reduce((a, b) => a + b, 0);
  self.postMessage(sum);
});

Виды workers и смежные возможности

  • Dedicated Worker — worker, связанный с одним создавшим его контекстом.
  • Shared Worker — может использоваться несколькими одноимёнными контекстами в поддерживаемых сценариях.
  • Service Worker — отдельный сценарий для перехвата сетевых запросов, кэширования, офлайн-поведения и push-событий; работает с ограниченным жизненным циклом и обычно требует HTTPS.
  • Worklet — специализированная лёгкая среда для конкретных операций, например обработки графики или аудио.
  • Atomics и SharedArrayBuffer — механизмы совместной памяти и синхронизации между агентами при выполнении требований безопасности, включая cross-origin isolation.
Worker не превращает любой код в параллельный автоматически. Нужно отдельно спроектировать передачу данных, синхронизацию, обработку ошибок и завершение фоновой задачи.

Для живого примера нужен включённый JavaScript. Код и пояснения показаны в блоках рядом.

22. Безопасность клиентского JavaScript

Клиентский код выполняется на устройстве пользователя и не может считаться доверенной границей приложения. Пользователь способен изменить JavaScript, DOM, локальное состояние и отправляемые запросы. Проверка прав и критических данных должна выполняться на сервере.

XSS: внедрение исполняемого содержимого

Cross-Site Scripting возникает, когда недоверенные данные обрабатываются так, что становятся исполняемым кодом или небезопасной разметкой.

// Небезопасно для недоверенного пользовательского текста:
element.innerHTML = userInput;

// Для обычного текста безопаснее:
element.textContent = userInput;

Если действительно нужно отображать пользовательский HTML, требуется проверенный санитайзер и продуманная политика доверенных типов. Простая замена нескольких символов вручную не является надёжной очисткой HTML.

Другие важные риски

  • CSRF — попытка заставить браузер авторизованного пользователя выполнить нежелательный запрос. Используют подходящие cookie-политики, CSRF-токены и серверную проверку происхождения запросов.
  • CORS — механизм контроля доступа к междоменным ответам, а не универсальная защита API от злоупотреблений.
  • CSP — Content Security Policy ограничивает источники и виды исполняемого контента.
  • Clickjacking — обман пользователя через встраивание интерфейса в чужой контекст; важны заголовки и политики встраивания.
  • Утечка секретов — любой секрет, встроенный в клиентский JS-бандл, доступен пользователю и не может считаться секретом.
  • Недоверенные зависимости — сторонний пакет получает возможности кода приложения в той же среде выполнения.
Принцип: никогда не полагайся на скрытую кнопку, проверку JavaScript или значение в localStorage как на механизм авторизации. Сервер должен проверять личность, права и корректность каждого критически важного запроса.

23. Производительность

Цель оптимизации — не просто уменьшить время вычисления, а сделать приложение отзывчивым: быстро показывать полезный контент, реагировать на действия и не блокировать главный поток.

Практические направления

  • Не выполнять тяжёлые вычисления в обработчиках событий и длинных синхронных задачах.
  • Использовать Web Workers для действительно тяжёлых независимых вычислений.
  • Ограничивать частоту дорогих обработчиков прокрутки и изменения размеров; рассматривать requestAnimationFrame(), throttle и debounce по назначению.
  • Не создавать и не изменять DOM без необходимости; группировать операции.
  • Удалять ненужные обработчики и ссылки, чтобы объекты могли быть освобождены сборщиком мусора.
  • Разделять код на модули и загружать редко используемые части по требованию.
  • Следить за объёмом JavaScript, стоимостью зависимостей и количеством сетевых запросов.
  • Измерять реальные показатели, а не оптимизировать на основе догадок.

Полезные механизмы

МеханизмНазначение
requestAnimationFrame()Планирует работу перед следующим обновлением кадра для визуальных изменений.
requestIdleCallback()Позволяет планировать некритичную работу в периоды простоя; поддержка и пригодность ограничены, требуется fallback.

DevTools

Инструменты разработчика браузера обычно включают:

  • Console — выполнение команд, сообщения и ошибки.
  • Sources / Debugger — исходники, точки останова, пошаговое выполнение, стек вызовов.
  • Network — запросы, заголовки, ответы, время и объём передачи.
  • Performance — профилирование задач, кадры и узкие места.
  • Memory — исследование использования памяти и утечек.
  • Application / Storage — cookies, localStorage, IndexedDB, Service Workers и кэш.
  • Elements — DOM, вычисленные стили и связанные изменения.

Виды тестирования

Unit-тесты

Проверяют отдельные функции и небольшие модули.

Интеграционные тесты

Проверяют совместную работу частей приложения и API.

End-to-end

Проверяют сценарии через реальный браузер или близкое к нему окружение.

25. Архитектура клиентского кода

Когда приложение растёт, важно разделить ответственность и не превращать один файл или один обработчик событий в место, где выполняется вся логика.

Типичное разделение

Представление (UI)

Отображение данных, DOM, состояния визуальных компонентов и взаимодействие с пользователем.

Бизнес-логика

Правила предметной области, проверки, вычисления, сценарии и переходы состояний.

Доступ к данным

HTTP-клиент, сериализация, кэширование, работа с хранилищем.

Инфраструктура

Конфигурация, логирование, обработка ошибок, метрики и интеграции.

Нативный JavaScript и фреймворки

В небольшом проекте можно обойтись HTML, CSS и нативным JavaScript. Для сложных приложений часто используют библиотеки или фреймворки, например React, Vue, Angular, Svelte. Они помогают организовать компоненты, состояние и обновление интерфейса, но не заменяют HTML, CSS, JavaScript и браузерные API.

Типизация

JavaScript динамически типизирован. TypeScript добавляет статическую систему типов и компилируется/транспилируется в JavaScript. Браузер обычно исполняет получившийся JavaScript, а не TypeScript как таковой. Типизация помогает проектировать API и обнаруживать ошибки до запуска, но не заменяет проверку входных данных во время выполнения.

26. Совместимость, стандарты и новые возможности

Язык и Web API развиваются через стандарты и предложения. Новая синтаксическая возможность в проекте спецификации не обязательно доступна в стабильных браузерах. Даже стандартизированный интерфейс может иметь различную поддержку или ограничения в конкретных условиях.

Как проверять поддержку

  1. Уточнить точное название интерфейса или синтаксиса в документации.
  2. Посмотреть таблицу совместимости и минимальные версии браузеров.
  3. Проверить наличие API в целевой среде, например через проверку свойства.
  4. Реализовать альтернативный сценарий (fallback), когда это необходимо.
  5. Проверить поведение на реальных целевых браузерах и устройствах.
if ("IntersectionObserver" in window) {
  // Современный путь
} else {
  // Упрощённый запасной вариант
}

Не следует проверять браузер по строке user-agent, если можно проверить конкретную возможность. Feature detection обычно надёжнее определения названия браузера.

Для живого примера нужен включённый JavaScript. Код и пояснения показаны в блоках рядом.

Контекст на ноябрь 2026 года: опубликован ECMAScript 2026; работа над будущими редакциями продолжается. Для реального проекта следует сверять поддержку каждой нужной функции с целевой матрицей браузеров и актуальными данными совместимости.

27. Практические задания

Задачи расположены от простых к более комплексным. Их цель — не заучивание синтаксиса, а умение связать язык с интерфейсом и браузерной средой.

Уровень 1. Основа языка

  1. Напиши функцию, которая принимает два числа и возвращает их сумму, разность, произведение и частное.
  2. Получив массив оценок, вычисли среднее значение, максимальную и минимальную оценку.
  3. Сгруппируй массив объектов пользователей по признаку активности.
  4. Создай объект товара и функцию, которая формирует его краткое текстовое описание.

Уровень 2. DOM и события

  1. Создай список задач: добавление новой задачи, отметка выполнения и удаление.
  2. Реализуй фильтр списка по введённой строке.
  3. Создай форму регистрации с валидацией и выводом ошибок возле полей.
  4. Сделай счётчик нажатий, используя addEventListener.

Уровень 3. Асинхронность и сеть

  1. Загрузи JSON с тестового API через Fetch и отобрази список данных.
  2. Добавь состояния загрузки, пустого результата и ошибки.
  3. Реализуй отмену предыдущего запроса при быстром изменении поискового запроса.
  4. Создай мини-чат на основе WebSocket или демонстрацию двустороннего обмена сообщениями.

Уровень 4. Браузерные API и архитектура

  1. Сохраняй настройки темы в localStorage.
  2. Сделай офлайн-кэширование статических ресурсов с Service Worker.
  3. Вынеси тяжёлое вычисление в Web Worker.
  4. Раздели приложение на модули: интерфейс, данные, бизнес-логика и конфигурация.
Критерий освоения: ты можешь объяснить, что именно выполняет язык, что делает браузер, где находится состояние и как данные проходят от действия пользователя до результата на экране.
