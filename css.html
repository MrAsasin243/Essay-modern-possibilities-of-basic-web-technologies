CSS: как браузер оформляет и размещает элементы

CSS (Cascading Style Sheets, каскадные таблицы стилей) описывает представление структурированного документа. С его помощью задают цвета, типографику, размеры, расположение элементов, адаптивное поведение, визуальные состояния, переходы и анимации.

1. Что такое CSS и за что он отвечает

CSS — декларативный язык описания внешнего представления HTML- и других структурированных документов.

HTML сообщает, какие элементы и смысловые части есть в документе. CSS определяет, как эти элементы должны выглядеть и участвовать в компоновке: какой у них цвет, шрифт, размер, отступы, положение, поведение при нехватке места и визуальная реакция на состояния.

HTML

Содержание и семантика: заголовок, абзац, список, кнопка, форма.

CSS

Представление: типографика, цвет, размеры, расположение, адаптивность.

JavaScript

Программная логика: вычисления, обработчики событий, запросы и динамика.

CSS не ограничивается «раскрашиванием» страницы. Он управляет алгоритмами компоновки: нормальным потоком, Flexbox, Grid, многоколоночной раскладкой, позиционированием и другими моделями. CSS также умеет описывать анимации, реагировать на состояния элементов и условия среды — например, ширину окна, предпочтение тёмной темы или настройку уменьшения движения.

Ключевая идея: CSS описывает правила и ограничения, а браузер вычисляет итоговые значения и применяет алгоритмы отображения. Разработчик обычно не задаёт координаты каждого пикселя вручную.

CSS развивается модульно: отдельные части стандарта описывают селекторы, каскад, размеры, цвет, сетки, анимации и другие области. Поэтому «CSS» — не одна небольшая спецификация, а семейство взаимосвязанных модулей.

2. Как CSS обрабатывается браузером

Когда браузер встречает CSS, он загружает таблицы стилей, разбирает их синтаксис и строит внутреннее представление правил — CSSOM (CSS Object Model). Затем браузер сопоставляет селекторы с элементами документа и вычисляет итоговые значения свойств с учётом каскада, наследования и значений по умолчанию.

2.1. CSSOM

CSSOM — объектная модель CSS. Она представляет таблицы стилей, правила и декларации в форме, с которой может работать браузер. JavaScript может обращаться к CSSOM через интерфейсы вроде document.styleSheets и CSSStyleSheet, а также читать вычисленный стиль элемента через getComputedStyle().

2.2. Computed style и итоговое значение

Значение, написанное в файле, не всегда совпадает с тем, что браузер в итоге использует. Например, единицы могут быть преобразованы, проценты — рассчитаны относительно контекста, наследуемые значения — получены от родителя, а неопределённое свойство — принять начальное значение.

/* Авторское правило */
.card {
  width: 50%;
  color: inherit;
  margin-inline: auto;
}

/* JavaScript может запросить вычисленный стиль */
const card = document.querySelector(".card");
const styles = getComputedStyle(card);
console.log(styles.width);
console.log(styles.color);

Важно: вычисленный стиль не является готовой картинкой и не обязательно совпадает с фактическим количеством физических пикселей на дисплее. Между CSS и экраном находятся этапы компоновки, отрисовки, масштабирования и композитинга.

3. Способы подключения CSS к HTML

3.1. Внешняя таблица стилей — основной способ

<head>
  <link rel="stylesheet" href="styles/main.css">
</head>

CSS хранится в отдельном файле. Это облегчает повторное использование стилей, разделение ответственности, кеширование и сопровождение проекта.

3.2. Встроенный блок <style>

<head>
  <style>
    body {
      font-family: system-ui, sans-serif;
    }
  </style>
</head>

Правила находятся непосредственно в HTML-документе. Подходит для небольших страниц, демонстраций и стилей, специфичных для одного документа.

3.3. Атрибут style

<p style="color: crimson; font-weight: 700;">
  Важное сообщение
</p>

Это inline-стиль. Он часто усложняет управление оформлением и проигрывает хорошей архитектуре внешних таблиц. Inline-декларации также имеют особое место в каскаде.

3.4. @import

@import url("typography.css");

body {
  margin: 0;
}

@import подключает другую таблицу стилей из CSS. Он полезен в некоторых случаях композиции стилей, но может повлиять на обнаружение и загрузку ресурсов. В типичных приложениях явное подключение файлов через HTML часто проще для управления загрузкой.

4. Синтаксис CSS

Основная конструкция CSS называется правилом (CSS rule). В простом правиле есть селектор и блок деклараций.

/* Селектор выбирает элементы */
h1 {
  color: #253b80;       /* свойство: значение */
  font-size: 2rem;
  margin-block: 0 1rem;
}

Составные части:

  • Селектор — описывает, к каким элементам применить правило.
  • Декларация — пара «свойство: значение».
  • Свойство — характеристика, которую можно изменить: color, width, display.
  • Значение — выбранная настройка свойства: red, 20px, grid.

4.1. Несколько правил и комментарии

h1, h2, h3 {
  font-family: Georgia, serif;
}

/* Комментарии не отображаются на странице. */
.note {
  border-left: 4px solid royalblue;
  padding: 1rem;
}

4.2. At-rules — директивы CSS

At-rule начинается с символа @ и управляет специальной частью таблицы стилей.

ДирективаНазначение

@layerУправление слоями каскада.
@font-faceОбъявление подключаемого шрифта.
@keyframesКлючевые кадры анимации.
@propertyРегистрация типизированного пользовательского свойства.

Если браузер встречает неизвестное или некорректное объявление, он обычно отбрасывает соответствующее объявление или правило по правилам парсинга, а не прекращает обработку всего файла. Это позволяет CSS постепенно развиваться.

5. Селекторы: как выбрать элементы

Селектор задаёт условие, по которому браузер определяет элементы, к которым применяются декларации.

5.1. Комбинаторы — отношения между элементами

article p       /* любой p внутри article */
article > p     /* p — непосредственный ребёнок article */
h2 + p           /* p сразу после h2 на том же уровне */
h2 ~ p           /* все последующие соседние p на том же уровне */
.card.active     /* один элемент одновременно с двумя классами */

Комбинаторы позволяют выбирать элементы по их положению в дереве документа. Они не перемещают элементы и не меняют HTML — только определяют, к каким узлам применить правила.

5.2. Псевдоклассы

Псевдокласс выбирает элемент по состоянию, положению в структуре или другим условиям. Он начинается с одного двоеточия.

button:hover { background: #294bb0; }
input:focus-visible { outline: 3px solid orange; }
input:invalid { border-color: crimson; }
li:first-child { font-weight: 700; }
tr:nth-child(even) { background: #f5f7fb; }
.card:not(.featured) { opacity: .85; }
form:has(input:invalid) { border-color: crimson; }
ГруппаПримерыНазначение
Состояния взаимодействия:hover, :active, :focus, :focus-visibleНаведение, нажатие, фокус.
Формы:checked, :disabled, :required, :valid, :invalidСостояние полей и управляющих элементов.
Структура:first-child, :last-child, :nth-child(), :only-childПоложение относительно соседей.
Логические:is(), :where(), :not(), :has()Комбинирование условий и выбор по наличию потомков.
Документ и навигация:root, :target, :lang(), :definedСостояние документа, URL и языка.

5.3. Псевдоэлементы

Псевдоэлементы позволяют стилизовать определённую часть элемента или создать декоративную область, не добавляя отдельный HTML-элемент.

.notice::before {
  content: "Важно: ";
  font-weight: 700;
}

p::first-letter { font-size: 2em; }
::selection { background: #dce5ff; }
input::placeholder { color: #7b8497; }
li::marker { color: royalblue; }

Для ::before и ::after обычно необходимо задать content. Они подходят для декоративных маркеров и графических деталей, но не должны заменять важное содержимое, которое пользователь обязан прочитать или использовать.

6. Каскад, специфичность и наследование

Каскад — алгоритм, который разрешает конфликты, когда несколько CSS-деклараций задают разные значения одного свойства для одного элемента.

CSS расшифровывается как Cascading Style Sheets не случайно. На один элемент одновременно могут влиять правила браузера, таблицы автора сайта, пользовательские настройки, несколько подключённых файлов и inline-стили. Для каждого свойства браузер должен определить одно итоговое значение.

6.1. Упрощённая последовательность каскада

  1. Релевантность: исключаются правила, которые не относятся к элементу или не проходят условие @media, @supports и другие условия.
  2. Источник и важность: учитывается происхождение декларации (браузер, пользователь, автор сайта), флаг !important и слой каскада.
  3. Специфичность: сравнивается вес селекторов, если предыдущие критерии не разрешили конфликт.
  4. Близость области: для подходящих scoped-правил может учитываться близость к корню области @scope.
  5. Порядок исходного кода: при прочих равных побеждает правило, расположенное позже.
Не своди каскад к «id сильнее class». Специфичность сравнивается лишь после более ранних этапов каскада. Правило из более приоритетного источника или слоя может победить селектор с большим весом.

6.2. Специфичность

Для базовых селекторов удобно пользоваться условной тройкой (A, B, C):

  • A — количество селекторов идентификаторов (#id).
  • B — количество классов, атрибутов и псевдоклассов.
  • C — количество селекторов типов и псевдоэлементов.
СелекторУсловный вес
p(0, 0, 1)
.note(0, 1, 0)
#main(1, 0, 0)
article.note p(0, 1, 2)
:where(#main .note)(0, 0, 0)
:is(.note, #main)Максимальная специфичность среди аргументов: (1, 0, 0)

Тройка — удобная модель сравнения, а не буквальное число, которое складывают в одну сумму. Сравнение идёт по разрядам слева направо. Универсальный селектор *, комбинаторы и содержимое :where() не добавляют специфичности; :is(), :not() и :has() учитывают наиболее специфичный аргумент.

p { color: black; }
.article p { color: navy; }
#intro { color: darkred; }

/* Если элемент одновременно p.article и #intro,
   значение для #intro имеет больший вес селектора. */

Для живого примера нужен включённый JavaScript. Код и пояснения показаны в блоках рядом.

6.3. Наследование

Некоторые свойства передаются от родительского элемента к потомкам, если не задано другое значение. Чаще наследуются свойства текста, например color, font-family, font-size и line-height. Геометрические свойства, например margin, padding и border, обычно не наследуются.

body {
  color: #263248;
  font-family: system-ui, sans-serif;
}

/* Абзац унаследует цвет и семейство шрифта,
   если для него не задано другое значение. */

6.4. Глобальные значения

ЗначениеСмысл
inheritПринудительно взять значение у родителя.
initialИспользовать начальное значение свойства по спецификации.
unsetВести себя как inherit для наследуемого свойства, иначе как initial.

revert-layerОткатить значение к предыдущему слою каскада.

6.5. Слои каскада — @layer

Слои позволяют задать порядок приоритетов для крупных групп стилей. Это полезно, когда в проекте есть reset, базовые стили, компоненты, утилиты и сторонние библиотеки.

@layer reset, base, components, utilities;

@layer base {
  button { font: inherit; }
}

@layer components {
  .button { background: royalblue; color: white; }
}

@layer utilities {
  .text-center { text-align: center; }
}

Для живого примера нужен включённый JavaScript. Код и пояснения показаны в блоках рядом.

Для обычных авторских деклараций более поздний слой имеет приоритет над более ранним, а обычные правила вне слоёв — над обычными правилами внутри слоёв. Для !important порядок слоёв обращается. Это ещё одна причина не использовать !important как универсальный способ исправления конфликтов.

7. Значения, единицы измерения и CSS-функции

Свойства CSS принимают разные типы значений: числа, длины, проценты, углы, время, цвета, ключевые слова, URL и более сложные структуры. Важно знать не только единицу, но и то, относительно чего она вычисляется.

7.3. Пользовательские свойства — CSS variables

:root {
  --color-primary: #3157c8;
  --space-unit: 0.5rem;
  --radius-card: 1rem;
}

.card {
  color: var(--color-primary);
  padding: calc(3 * var(--space-unit));
  border-radius: var(--radius-card);
}

Для живого примера нужен включённый JavaScript. Код и пояснения показаны в блоках рядом.

Пользовательские свойства с префиксом -- участвуют в каскаде и обычно наследуются. Их можно переопределять на отдельных элементах, что удобно для тем, дизайн-токенов и повторно используемых компонентов. При необходимости для пользовательского свойства можно задать тип, начальное значение и правила наследования через @property.

8. Цвета и прозрачность

CSS поддерживает именованные цвета, шестнадцатеричную запись, RGB, HSL и более новые цветовые модели.

.examples {
  color: navy;
  background: #f1f4ff;
  border-color: rgb(40 70 150 / 65%);
  outline-color: hsl(220 75% 45%);
  box-shadow: 0 0 0 4px oklch(80% 0.12 250 / 40%);
}

Среди цветовых функций и пространств: rgb(), hsl(), hwb(), lab(), lch(), oklab(), oklch(), color() и color-mix(). Новые пространства позволяют более точно работать с восприятием светлоты и насыщенности и создавать плавные переходы между цветами.

8.1. Цвет и прозрачность — не одно и то же, что видимость

  • Альфа-канал цвета делает прозрачным конкретный цветовой слой.
  • opacity меняет непрозрачность всего элемента вместе с потомками и может создавать новый stacking context.
  • visibility: hidden скрывает элемент, но обычно сохраняет занимаемое им место в раскладке.
  • display: none исключает элемент из обычной компоновки.
Доступность: цвет не должен быть единственным способом передать смысл. Например, ошибку поля нужно обозначать не только красной рамкой, но и текстом или другим понятным индикатором. Проверяй контраст текста и фона.

9. Блочная модель — Box Model

В обычной CSS-компоновке каждый элемент участвует в создании прямоугольных областей. Классическая блочная модель включает содержимое, внутренние отступы, границу и внешние отступы.

.box {
  width: 300px;
  padding: 20px;
  border: 5px solid steelblue;
  margin: 16px;
  box-sizing: content-box;
}

При content-box заданная ширина относится только к содержимому. В приведённом примере внешняя ширина рамки составит 350 CSS-пикселей: 300 + 40 внутреннего отступа + 10 границы. Внешние отступы в эту ширину не входят.

*,
*::before,
*::after {
  box-sizing: border-box;
}

При border-box заданная ширина включает содержимое, padding и border. Такой подход часто делает расчёт размеров предсказуемее.

Для живого примера нужен включённый JavaScript. Код и пояснения показаны в блоках рядом.

9.1. Margin collapse и overflow

В некоторых случаях вертикальные внешние отступы соседних блочных элементов схлопываются: вместо суммы используется один отступ по правилам margin collapsing. Это не универсальное поведение всех направлений и всех типов контейнеров.

Свойство overflow управляет содержимым, выходящим за границы области: visible, hidden, clip, scroll и auto. Оно важно для прокрутки, обрезания и создания некоторых контекстов форматирования.

.scroll-panel {
  max-height: 18rem;
  overflow: auto;
}

.image-frame img {
  width: 100%;
  aspect-ratio: 16 / 9;
  object-fit: cover;
}

10. Типы отображения и потоки компоновки

Свойство display определяет, какой тип CSS-бокса создаёт элемент и как его содержимое участвует в компоновке. Значение display — не просто переключатель «показать/скрыть».

ЗначениеОсновной смысл
blockБлочный тип: обычно начинает новую строку и занимает доступную ширину.
inlineСтрочный тип: участвует в строковом потоке текста.
inline-blockВедёт себя как строчный элемент с блочной геометрией.
flow-rootСоздаёт независимый контекст блочного форматирования.
flex, inline-flexВключает Flexbox для непосредственных дочерних элементов.
grid, inline-gridВключает CSS Grid.
table и связанные значенияКомпоновка с табличной моделью.
list-itemСоздаёт маркер списка и основной блок.
noneЭлемент не создаёт собственных боксов и не участвует в раскладке.
contentsСам элемент не создаёт обычный контейнерный бокс; его содержимое участвует дальше в раскладке.

10.1. Нормальный поток

Если специально не задан другой режим, элементы располагаются в нормальном потоке. Блочные элементы последовательно располагаются вдоль блочной оси, а строчное содержимое формирует строки и переносится при нехватке места.

CSS также поддерживает независимые контексты форматирования, например BFC (Block Formatting Context). Их создание может изолировать поведение float, margin collapsing и другие эффекты. Один из явных способов создать BFC — display: flow-root.

10.2. Видимость

СвойствоВизуально скрыт?Место в раскладке
display: noneДаНе занимает место.
visibility: hiddenДаОбычно сохраняется.
opacity: 0ДаСохраняется; элемент может продолжать получать события.

Сокрытие визуально не всегда означает удаление из клавиатурного или accessibility-взаимодействия. Для реальных интерфейсных сценариев нужно выбирать механизм в соответствии с требуемым поведением.

11. Позиционирование и управление слоями

Свойство position определяет способ позиционирования элемента. Смещения обычно задают через top, right, bottom, left или логические свойства inset-block и inset-inline.

ЗначениеПоведение
staticОбычное положение в нормальном потоке; смещения не применяются.
relativeСохраняет место в потоке, но визуально смещается относительно своего исходного положения; часто создаёт containing block для absolute-потомков.
absoluteИсключается из нормального потока и позиционируется относительно своего containing block.
fixedОбычно позиционируется относительно viewport, но некоторые предки могут изменить containing block.
stickyСначала ведёт себя как элемент потока, затем может закрепляться в пределах scroll-контейнера.
 
.card {
  position: relative;
}

.card__badge {
  position: absolute;
  inset-block-start: 1rem;
  inset-inline-end: 1rem;
}

.site-header {
  position: sticky;
  inset-block-start: 0;
  z-index: 10;
}

11.1. Containing block

Containing block — прямоугольная область, относительно которой рассчитываются некоторые размеры и координаты. Для абсолютно позиционированного элемента это часто ближайший позиционированный предок, но правила сложнее: содержащий блок могут создавать также трансформации, фильтры и некоторые другие свойства.

11.2. z-index и stacking context

z-index участвует в порядке наложения элементов внутри контекста наложения. Нельзя считать его одной глобальной шкалой для всей страницы: дочерний элемент не может произвольно «вылезти» выше чужого родительского stacking context.

Контексты наложения создаются, среди прочего, некоторыми позиционированными элементами с z-index, элементами с opacity меньше единицы, трансформациями, фильтрами и isolation: isolate.

Когда кажется, что «z-index не работает», проверь не только числовое значение, но и stacking context предков, содержащий блок и контекст позиционирования.

12. Flexbox — одномерная компоновка

Flexbox предназначен для размещения элементов вдоль одной главной оси: в строку или столбец. Он удобен для навигации, панелей инструментов, групп кнопок, карточек и выравнивания элементов внутри компонента.

.toolbar {
  display: flex;
  flex-direction: row;
  justify-content: space-between;
  align-items: center;
  gap: 1rem;
}

.toolbar__actions {
  display: flex;
  gap: .5rem;
}

12.1. Свойства flex-контейнера

СвойствоНазначение
flex-directionНаправление главной оси: row, row-reverse, column, column-reverse.
flex-wrapРазрешает перенос элементов на новые строки.
flex-flowСокращение для direction и wrap.
justify-contentРаспределение вдоль главной оси.
align-itemsВыравнивание элементов по поперечной оси одной линии.
align-contentРаспределение линий, когда есть несколько flex-линий и свободное место.
gapИнтервалы между элементами и линиями.

12.2. Свойства flex-элементов

  • flex-grow — насколько элемент может увеличиваться относительно других элементов.
  • flex-shrink — насколько элемент может сжиматься.
  • flex-basis — исходный базовый размер до распределения свободного пространства.
  • flex — сокращённая запись этих трёх параметров.
  • align-self — индивидуальное поперечное выравнивание.
  • order — изменение визуального порядка flex-элемента; не меняет порядок в DOM и последовательность чтения.
.item {
  flex: 1 1 16rem;
}

.item--fixed {
  flex: 0 0 12rem;
}

Для живого примера нужен включённый JavaScript. Код и пояснения показаны в блоках рядом.

Важный практический нюанс: у flex-элементов минимальный размер по умолчанию может зависеть от содержимого. Если элемент неожиданно не сжимается, иногда требуется явно задать min-width: 0 или min-inline-size: 0.

Flexbox обычно выбирают для одномерной компоновки. Если нужно одновременно контролировать строки и столбцы как сетку, чаще удобнее Grid.

13. CSS Grid — двумерная компоновка

CSS Grid предназначен для компоновки по строкам и столбцам одновременно. Он особенно полезен для макетов страниц, каталогов, галерей и сложных интерфейсных панелей.

.dashboard {
  display: grid;
  grid-template-columns: 15rem minmax(0, 1fr);
  grid-template-rows: auto 1fr auto;
  gap: 1rem;
}

.card-grid {
  display: grid;
  grid-template-columns: repeat(
    auto-fit,
    minmax(min(100%, 15rem), 1fr)
  );
  gap: 1rem;
}

13.1. Основные понятия

  • Grid container — элемент с display: grid или inline-grid.
  • Grid item — непосредственный дочерний элемент сетки.
  • Track — дорожка, строка или столбец сетки.
  • Grid line — линия, ограничивающая дорожки.
  • Grid area — прямоугольная область из одной или нескольких ячеек.
  • Gap — промежуток между дорожками.

13.2. Основные свойства

СвойствоНазначение
grid-template-columnsОпределяет дорожки столбцов.
grid-template-rowsОпределяет дорожки строк.
grid-template-areasЗадаёт именованные области сетки.
grid-auto-columns/rowsРазмеры неявно создаваемых дорожек.
grid-column, grid-rowРазмещение элементов по линиям.
grid-auto-flowАлгоритм автоматического размещения.

13.3. Именованные области

.page {
  display: grid;
  grid-template-columns: 16rem 1fr;
  grid-template-areas:
    "header header"
    "sidebar content"
    "footer footer";
  gap: 1rem;
}

13.4. Автоматические дорожки и subgrid

repeat(), minmax(), auto-fit и auto-fill позволяют создавать адаптивные сетки без отдельного media query для каждого количества столбцов. subgrid позволяет вложенной сетке использовать дорожки родительской сетки — это полезно, когда элементы в разных карточках должны согласовывать строки или столбцы.

.catalog {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(14rem, 1fr));
  gap: 1rem;
}

14. Другие механизмы компоновки

Flexbox и Grid — не единственные средства CSS. Существуют специализированные модели, которые подходят для определённых типов контента.

14.1. Float и обтекание

float изначально предназначался для обтекания изображения текстом. Сейчас он полезен для редакционного контента, но не является предпочтительным способом создания общей сетки сайта.

.article-image {
  float: inline-start;
  width: min(40%, 18rem);
  margin-inline-end: 1rem;
}

clear управляет тем, может ли элемент располагаться рядом с float-элементами.

14.2. Многоколоночная раскладка

.long-text {
  columns: 2 18rem;
  column-gap: 2rem;
  column-rule: 1px solid #d8deea;
}

Многоколоночная модель подходит для журнального текста и длинных списков. Она автоматически разбивает содержимое на колонки, а не строит независимую сетку карточек.

14.3. Выравнивание

CSS Box Alignment предоставляет общие механизмы выравнивания в Grid, Flexbox и других моделях. Основные свойства — justify-content, align-content, justify-items, align-items, justify-self, align-self и сокращения place-content, place-items, place-self. Точный смысл осей зависит от режима компоновки.

14.4. Scroll Snap и управление прокруткой

.gallery {
  display: grid;
  grid-auto-flow: column;
  grid-auto-columns: 85%;
  overflow-x: auto;
  scroll-snap-type: x mandatory;
  gap: 1rem;
}

.gallery > * {
  scroll-snap-align: start;
}

Свойства scroll-snap-type и scroll-snap-align помогают организовать привязку прокрутки к определённым точкам. Рядом с ними существуют scroll-behavior, scroll-margin, scroll-padding и overscroll-behavior.

15. Типографика и оформление текста

Типографика влияет не только на внешний вид, но и на читаемость, плотность информации и доступность документа.

}

15.1. Подключение собственных шрифтов

@font-face {
  font-family: "Project Sans";
  src: url("/fonts/project-sans.woff2") format("woff2");
  font-weight: 100 900;
  font-style: normal;
  font-display: swap;
}

@font-face объявляет шрифт, который браузер может загрузить и использовать. Нужно учитывать лицензии, объём файлов, подмножества символов, fallback-шрифты и стратегию отображения до загрузки шрифта.

15.2. Writing modes и логические свойства

Свойства writing-mode, direction и text-orientation позволяют учитывать разные направления письма. Логические свойства — margin-inline-start, padding-block, border-inline-end, inset-inline — привязывают оформление к понятиям inline/block, а не к физическим left/right/top/bottom. Это упрощает поддержку RTL-языков и вертикального письма.

16. Фоны, рамки, тени и визуальные эффекты

CSS включает большое семейство свойств для оформления поверхностей и визуальных слоёв.

16.1. Фоны и градиенты

.hero-panel {
  background-color: #1d3268;
  background-image:
    radial-gradient(circle at top right, #7894ff, transparent 40%),
    linear-gradient(120deg, #142347, #3157c8);
  background-position: center;
  background-size: cover;
}

Можно задавать несколько фоновых слоёв, изображения, повторение, размер, позицию и способ смешивания.

16.2. Границы и тени

.panel {
  border: 1px solid #dce2ef;
  border-radius: 1rem;
  box-shadow: 0 1rem 2rem rgb(20 35 70 / 12%);
}

Дополнительно доступны outline, контуры, рамки изображений, внутренние и внешние тени, индивидуальный радиус углов и свойства для управления фоном внутри границы.

16.3. Маски, обрезка и фильтры

.avatar {
  width: 8rem;
  aspect-ratio: 1;
  object-fit: cover;
  clip-path: circle(50%);
}

.photo:hover {
  filter: saturate(1.15) contrast(1.05);
}

К инструментам эффектов относятся filter, backdrop-filter, clip-path, mask, mix-blend-mode, background-blend-mode и различные SVG-фильтры. Их следует применять осмысленно: сложные фильтры и большие полупрозрачные поверхности могут увеличивать нагрузку на графический конвейер.

17. Адаптивный дизайн — Responsive Design

Адаптивный интерфейс подстраивается под доступное пространство и условия устройства. Он должен оставаться читаемым и управляемым не только на конкретной модели телефона, но и при изменении ширины окна, масштаба, ориентации и настроек пользователя.

17.1. Mobile-first

Один из распространённых подходов — сначала описать базовый вариант для узкого экрана, а затем добавлять улучшения по мере появления свободного пространства.

/* Базовый вариант — одна колонка */
.layout {
  display: grid;
  grid-template-columns: 1fr;
  gap: 1rem;
}

/* Когда пространства достаточно — две колонки */
@media (width >= 48rem) {
  .layout {
    grid-template-columns: 16rem minmax(0, 1fr);
  }
}

Breakpoints стоит выбирать по моменту, когда конкретный контент перестаёт удобно помещаться, а не только по названиям устройств.

17.2. Media Queries

Media queries позволяют применить CSS при выполнении условий о viewport, типе устройства вывода и предпочтениях пользователя.

/* Портретная ориентация */
@media (orientation: portrait) {
  .sidebar { display: none; }
}

/* Пользователь предпочитает тёмную палитру */
@media (prefers-color-scheme: dark) {
  :root {
    color-scheme: dark;
    --surface: #171c28;
    --text: #edf1f8;
  }
}

/* Пользователь просит уменьшить движение */
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    scroll-behavior: auto;
    animation-duration: .01ms !important;
    transition-duration: .01ms !important;
  }
}

Другие полезные media features: width, height, aspect-ratio, resolution, hover, pointer, prefers-contrast, forced-colors и print.

17.3. Container Queries

Media query обычно проверяет характеристики viewport или устройства. Container query позволяет компоненту адаптироваться к размеру своего контейнера. Это особенно полезно для повторно используемых карточек и виджетов: одна карточка может находиться в узкой боковой панели или в широком основном столбце.

.card-list {
  container-type: inline-size;
  container-name: cards;
}

.card {
  display: grid;
  grid-template-columns: 1fr;
  gap: 1rem;
}

@container cards (width >= 36rem) {
  .card {
    grid-template-columns: 10rem minmax(0, 1fr);
  }
}

Единицы cqw, cqh, cqi и cqb позволяют задавать длины относительно query-контейнера. Для проверки размера контейнера требуется соответствующий containment-контекст, например container-type: inline-size.

Для живого примера нужен включённый JavaScript. Код и пояснения показаны в блоках рядом.

17.4. Progressive Enhancement и @supports

.card {
  display: block;
}

@supports (display: grid) {
  .card-list {
    display: grid;
    grid-template-columns: repeat(auto-fit, minmax(16rem, 1fr));
  }
}

Прогрессивное улучшение означает, что базовый интерфейс остаётся пригодным, а современные возможности добавляются там, где браузер их поддерживает. Для проверки реальной поддержки конкретной функции используй таблицы совместимости, а не только наличие свойства в черновике стандарта.

18. Состояния элементов и интерактивные интерфейсы

CSS может менять оформление в ответ на состояние элемента, не выполняя JavaScript. Это не заменяет программную логику, но позволяет оформлять фокус, наведение, выбор, валидацию и некоторые состояния взаимодействия.

button {
  background: #3157c8;
  color: white;
  border: 0;
  border-radius: .6rem;
  padding: .7rem 1rem;
}

button:hover { background: #2547ad; }
button:active { transform: translateY(1px); }
button:focus-visible {

18.1. Акцент, курсор и события указателя

cursor задаёт вид курсора; pointer-events управляет тем, как элемент может быть целью указательных событий; accent-color задаёт акцентный цвет некоторых встроенных управляющих элементов. Свойство appearance влияет на нативное оформление контролов, но полное переоформление форм требует внимательной работы с доступностью и состояниями.

18.2. Псевдоклассы интерактивности

Особенно полезны :focus-visible, :focus-within, :checked, :disabled, :enabled, :required, :valid, :invalid, :placeholder-shown, :target и :has().

Не убирай outline без замены. Видимый фокус нужен людям, управляющим сайтом клавиатурой. Визуальная индикация должна сохраняться и быть различимой.

19. Трансформации, переходы и анимации

CSS позволяет изменять визуальное состояние элементов плавно, по времени или по ключевым кадрам.

19.1. Transforms

.card:hover {
  transform: translateY(-4px) scale(1.02);
}

.logo {
  transform: rotate(-6deg);
  transform-origin: center;
}

Трансформации включают перенос, масштабирование, вращение и наклон в 2D/3D. Связанные свойства: transform-origin, transform-style, perspective и backface-visibility.

19.2. Transitions

.button {
  background: royalblue;
  transform: translateY(0);
  transition:
    background-color 160ms ease,
    transform 160ms ease;
}

.button:hover {
  background: midnightblue;
  transform: translateY(-2px);
}

Переход интерполирует изменение значения между состояниями. Основные свойства: transition-property, transition-duration, transition-timing-function и transition-delay.

Для живого примера нужен включённый JavaScript. Код и пояснения показаны в блоках рядом.

19.3. @keyframes и animation

@keyframes pulse {
  0%, 100% { transform: scale(1); }
  50% { transform: scale(1.06); }
}

  animation: pulse 1.4s ease-in-out infinite;
}

Анимации могут управлять длительностью, задержкой, направлением, количеством повторений, режимом заполнения и состоянием воспроизведения. Для декоративного движения нужно учитывать prefers-reduced-motion.

Для живого примера нужен включённый JavaScript. Код и пояснения показаны в блоках рядом.

19.4. Scroll-driven animations и View Transitions

Современная CSS-платформа расширяет анимации за пределы обычного времени. Scroll-driven animations связывают прогресс анимации с прокруткой или видимостью элемента. View Transitions позволяют оформлять переходы между визуальными состояниями страницы; для полноценного управления переходом между состояниями обычно используется соответствующий браузерный API.

Эти возможности развиваются, а поддержка может отличаться по браузерам и версиям. Перед применением в критичном интерфейсе проверяй совместимость и предусматривай спокойный статический вариант.

20.1. CSS Nesting

.card {
  padding: 1rem;

  &:hover {
    border-color: royalblue;
  }

  .card__title {
    font-size: 1.25rem;
  }

  @media (width >= 50rem) {
    padding: 2rem;
  }
}

Вложенность позволяет держать связанные правила рядом. Не стоит строить чрезмерно глубокие цепочки: они затрудняют чтение и могут повышать специфичность вложенных селекторов.

20.2. @property

@property --progress {
  syntax: "<number>";
  inherits: false;
  initial-value: 0;
}

.meter {
  --progress: 0.6;
  transform: scaleX(var(--progress));
  transform-origin: left;
}

Регистрация сообщает браузеру допустимый тип пользовательского свойства и другие правила его обработки. Это позволяет браузеру лучше понимать значение, а в подходящих случаях — интерполировать его в анимациях.

21. Организация и архитектура CSS в проекте

CSS-файл может быстро превратиться в набор конфликтующих правил, если не договориться о структуре. Архитектура нужна для управляемости, повторного использования и предсказуемого каскада.

21.1. Разделение по назначению

styles/
  01-reset.css
  02-tokens.css
  03-base.css
  04-layout.css
  components/
    button.css
    card.css
    navigation.css
  utilities.css
  main.css

Это пример возможной структуры, а не обязательное правило. Для небольшого сайта может быть достаточно одного файла; для большой системы полезно разделять базовые стили, компоненты и дизайн-токены.

21.2. Подходы к именованию

  • BEM: блок, элемент и модификатор, например card, card__title, card--featured.
  • Utility classes: небольшие классы-утилиты, например text-center или mt-2.
  • Component-based: стили организуются вокруг повторно используемых UI-компонентов.
  • CSS Modules: механизм сборки, который локализует имена классов; это не отдельная функция языка CSS.

21.3. Препроцессоры и PostCSS

Sass/SCSS, Less и инструменты PostCSS расширяют или преобразуют CSS на этапе сборки. Они могут предоставлять дополнительные функции, переменные, миксины, преобразование синтаксиса и автопрефиксер. Не путай возможности языка CSS с возможностями инструмента сборки: браузер получает итоговый CSS, если только браузер не поддерживает исходную конструкцию нативно.

Практический ориентир: сначала изучи нативные CSS — каскад, custom properties, Grid, Flexbox, media/container queries. Затем станет понятнее, какую проблему решает конкретная библиотека или препроцессор.

22. Доступность, производительность и отладка

22.1. Доступность

  • Сохраняй заметный клавиатурный фокус; используй :focus-visible.
  • Проверяй контраст текста и фона.
  • Не передавай состояние только цветом.
  • Уважай prefers-reduced-motion.
  • Проверяй страницу при увеличении масштаба и изменении размера текста.
  • Не меняй визуальный порядок так, чтобы он противоречил порядку чтения и фокуса.
  • Не скрывай важное содержимое только ради визуального эффекта.

22.2. Производительность

Изменение разных CSS-свойств может запускать разную работу браузера. Изменение ширины или положения в обычном потоке может потребовать пересчёта layout; изменение цвета часто требует paint; некоторые трансформации могут быть обработаны на этапе compositing. Но это не абсолютные гарантии: конкретный путь зависит от браузера, контекста и графического конвейера.

  • Избегай ненужных крупных и частых изменений layout.
  • Не включай will-change без измеримой причины: оно не является универсальным ускорителем.
  • Ограничивай сложные фильтры, тени и большие полупрозрачные слои там, где они создают нагрузку.
  • Используй CSS containment и content-visibility только после понимания их побочных эффектов.
  • Проверяй реальную производительность через профилировщик браузера, а не по внешнему виду кода.

22.3. Отладка в DevTools

Панель Elements/Inspector показывает DOM, применённые правила, перечёркнутые декларации, специфичность, вычисленные стили и модель коробки. Можно временно менять значения, включать и отключать декларации, смотреть Grid/Flex overlays, проверять media queries и искать источник правила.

Полезный порядок диагностики: выбери элемент → открой computed styles → выясни, какое правило задало свойство → проверь каскад и специфичность → проверь размеры родителя и режим layout → проверь stacking context, если проблема связана с наложением.

23. Что CSS не делает самостоятельно

CSS умеет описывать представление и часть реакций на состояние, но не заменяет язык программирования или браузерные API.

25. Практика и источники

Лучше осваивать CSS не запоминанием сотен свойств, а короткими экспериментами: меняй одно правило, наблюдай результат в браузере и объясняй, почему произошло именно так.

25.1. Практические задания

  1. Подключение и селекторы. Создай HTML с заголовками, абзацами, ссылками и карточками. Подключи внешний CSS. Применяй типовые, классовые, атрибутные селекторы и комбинаторы.
  2. Каскад. Задай одно свойство несколькими правилами. Предскажи результат, затем проверь специфичность, источник, слой и порядок объявлений.
  3. Box Model. Создай карточку с width, padding, border и margin. Сравни content-box и border-box.
  4. Flexbox. Сделай панель навигации с логотипом слева и группой кнопок справа. Проверь поведение при узком окне.
  5. Grid. Сделай каталог карточек, автоматически меняющий число столбцов при изменении доступного пространства.
  6. Position. Добавь бейдж в угол карточки и закреплённую шапку. Разберись с containing block и z-index.
  7. Адаптивность. Добавь media query и container query. Сравни, на какие размеры они реагируют.
  8. Темы и доступность. Добавь тёмную тему, видимый keyboard focus и режим уменьшенного движения.
  9. Анимация. Создай небольшое наведение с transition и отдельную keyframes-анимацию. Уважай prefers-reduced-motion.
